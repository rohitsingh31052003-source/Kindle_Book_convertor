### 2. README requirement

The README's Milestone 2 requirement list includes **"Page-number removal"**.
M2.5 detects page-number *furniture* (as part of header/footer detection) and
M2.7 excludes only that detected furniture from the body. M2.10 establishes
the *explicit removal* operation this requirement asks for: a dedicated,
independently testable public function that consumes the integrated M2.7/M2.9
representation, identifies page-number artifacts that survived M2.5 (a
two-page `1, 2` bare-number sequence, or a single explicit `Page 7 of 20` on
a lone page), and returns a new document with those artifacts removed from
the body — proven by tests, with a documented removal contract.

### 3. Architecture

The removal layer sits **after M2.9** in the conceptual pipeline:

```
PDF → layout (M2.1) → reading order (M2.2/M2.6) → paragraphs (M2.3)
    → headings (M2.4) → header/footer analysis (M2.5) → reconstruction (M2.7)
    → chapter detection (M2.9) → page-number removal (M2.10)
```

Relative to the surrounding milestones:

- **M2.5**: detects and classifies page furniture; M2.10 does **not** rerun
  M2.5 scoring or duplicate it. M2.10 *reuses* M2.5's page-number patterns
  (`header_footer._page_number_key`), its geometry helpers
  (`_paragraph_bbox`, `_in_header_region` / `_in_footer_region`,
  `_normalize_text`, `_finite_positive`/`_valid_bbox` behavior), and its
  documented region constants (`HEADER_REGION_FRACTION`,
  `FOOTER_REGION_FRACTION`, `HEADER_POSITION_TOLERANCE_FRACTION`,
  `FOOTER_POSITION_TOLERANCE_FRACTION`) so the two milestones can never
  disagree about what a page-number form or a page-edge region is. The edge
  region tie-break is identical to M2.5's `_region_for` (header wins when a
  paragraph straddles both bands).
- **M2.7**: M2.10 consumes the `ReconstructedDocument` exactly as
  `reconstruct_layout` / `build_reconstructed_document` produce it — it
  reuses the existing element ordering, `ElementKind` classifications,
  paragraph provenance, and the `ParagraphLayout` page dimensions. It never
  re-extracts PDF text, re-sorts blocks, or re-runs paragraph/heading
  reconstruction.
- **M2.9**: M2.10 does not run chapter detection and does not depend on it.
  The `chapters` result is carried through the new document by reference, and
  a test proves `detect_chapters` produces identical results on the removed
  document.

M2.10 does **not** auto-integrate into `reconstruct_layout`: it is an
explicit, independently testable operation (the repository convention is
explicit per-milestone operations). Nothing in M2.7/M2.9 was changed.
### 4. Detection strategy

A paragraph is a **candidate** only when it is *both* a known page-number
form *and* located in a page-edge region. No single signal is decisive for
bare numbers.

- **Text patterns** — M2.5's `_page_number_key` (shared regexes) recognizes:
  `Page N`, `Page N of M`, `N / M`, `- N -`, and bare `N` (`\d{1,3}` only).
  The `N of M` template keeps the total concrete (`page n of 250`), so only
  genuinely similar forms group.
- **Geometry** — with page dimensions from the M2.7 `ParagraphLayout`
  (top-left origin, y-down, no assumed page size), a candidate's normalized
  top must be in the header band (`<= HEADER_REGION_FRACTION`) or its bottom
  in the footer band (`>= 1 - FOOTER_REGION_FRACTION`). Body-text numbers are
  never candidates. If the document has no paragraph layout (no real
  dimensions), nothing is guessed and nothing is removed.
- **Explicit forms at an edge** — `Page N`, `Page N of M`, `N / M`,
  `- N -` are unambiguous: removed on form + geometry alone.
- **Bare numbers** — removed only when they form a monotonic (ascending or
  descending) sequence of `MIN_BARE_SEQUENCE_PAGES` (2) distinct values on
  distinct pages at a consistent edge position (normalized spread within the
  M2.5 positional tolerance). The whole sequence is removed or none of it is.
  Sequences need not start at 1.
- **Positional consistency** — one representative per page; positions must
  agree within `HEADER_POSITION_TOLERANCE_FRACTION` /
  `FOOTER_POSITION_TOLERANCE_FRACTION` (0.03).
- **Document-level evidence** — everything above is computed across the whole
  document deterministically: repeated consistent-position candidates across
  pages plus a monotonic value sequence is the document-level signal.
- **Reuse of M2.5** — patterns, region helpers, and tolerance constants are
  imported from `header_footer`; M2.5's full furniture scoring is not.

Heuristic thresholds are named constants (`MIN_BARE_SEQUENCE_PAGES`) or
imported M2.5 constants; each is documented at its definition.

### 5. False-positive protection

The following are structurally outside the detection surface and can never be
removed:

- **Years** (`1947`, `2024`, `1999`) — four-digit numbers do not match the
  bare `\d{1,3}` pattern and are not explicit page-number forms, even at the
  page edge.
- **Dates, measurements, prices, numeric prose** (`5 June 2024`, `100 miles`,
  `$19.95`, `3.14`) — not page-number forms.
- **ISBNs / long numbers** — outside every pattern.
- **Numbered lists** — `1.` / `2.` text is not a page-number form; bare list
  markers in the body fail the geometry filter.
- **Chapters/sections and headings** — headings (`ElementKind.HEADING`) are
  skipped before any pattern check, so `Chapter 1`, `1. Introduction`, and
  even a bare numeric heading `5` at a page edge are preserved.
- **Ordinary isolated integers** — a lone bare number (or a non-monotonic or
  positionally inconsistent set) is reported as a *candidate* with
  `insufficient_sequence_evidence` but is left in the document. "It is a
  number" is never a page-number rule.

The one intentional relaxation versus M2.5 is documented:
`MIN_BARE_SEQUENCE_PAGES = 2` exists only for the narrow page-number-specific
case (a page-number *form* at an edge plus a monotonic two-value sequence);
M2.5's broader furniture scoring still requires 3 pages.
### 6. Result model/API

Public API (exported from `kindle_converter.pdf`):

- `remove_page_numbers(source: ReconstructedDocument) -> PageNumberRemovalResult`
  — validates `source` is a `ReconstructedDocument` (else `TypeError`,
  matching the project convention), never mutates it, and returns a new
  document plus the inspectable evidence.
- `PageNumberRemovalResult(dataclass, frozen, slots)` — `document` (new
  `ReconstructedDocument`), `removed` (`tuple[DetectedPageNumber, ...]`),
  `candidates` (`tuple[DetectedPageNumber, ...]`, every edge page-number-form
  considered), and a `removed_count` property. `candidates` ⊇ `removed`.
- `DetectedPageNumber(dataclass, frozen, slots)` — `text`, `page_number`,
  `value`, `location` (`PageNumberLocation`: `FOOTER` / `HEADER`),
  `reasons` (deterministic evidence tokens), `confidence` (deterministic
  heuristic in `[0, 1]`: 1.0 explicit forms, 0.9 sequenced bare numbers, 0.5
  kept candidates), and `source_paragraph` (the provenance link).
- `PageNumberLocation(StrEnum)`.
- `MIN_BARE_SEQUENCE_PAGES` constant.

All models are frozen dataclasses with slots, consistent with the document
domain (e.g. `ReconstructedDocument`, `DetectedHeaderFooter`).

### 7. Immutability/provenance

- The input `ReconstructedDocument` is never mutated: only the body `pages`
  are replaced by a filtered copy inside a newly constructed
  `ReconstructedDocument`; the upstream objects (`paragraphs`, `headings`,
  `header_footer`, `chapters`) are shared by reference.
- Tests prove immutability by *content and identity*, not only by `is`-check:
  the source element tuples are identical objects after removal, the source's
  full `(page_number, text)` sequence is unchanged, and the result is a
  different document object.
- Every `DetectedPageNumber` retains its `source_paragraph` by reference,
  with its `page_number` and original `text`, so every removed element can be
  traced back to its source reconstructed element. An internal invariant
  asserts (at removal time) that every removed paragraph is absent from the
  new body.
### 8. Tests

`tests/test_page_number_removal.py` (47 tests) covers:

- Basic bottom page numbers (`1 2 3 4` removed).
- Explicit forms: `Page N`, `page N`, `Page N of M`, `N / M`, `- N -`;
  a lone `Page 7 of 20`; `Page 1` wording in body prose is kept.
- Position consistency (consistent positions removed; inconsistent spread
  kept; small drift within tolerance removed).
- Sequence evidence (start at 5; non-monotonic kept; single isolated number
  is a candidate only).
- Years preserved (body and at the page edge), dates, measurements/prices/
  numeric prose, numbered lists, bare list markers in body text.
- Chapter headings (`Chapter 1 / 2 / 3`) remain intact and M2.9 still detects
  them on the removed document; numeric headings at the page edge are
  preserved; numbered section headings preserved.
- Mixed content (only page-number artifacts removed).
- Top-position (header) page numbers removed; isolated header number
  candidate-only.
- Different page sizes (non-A4, and per-page mixed sizes).
- Blank/empty document → empty deterministic result; document without a
  paragraph layout → conservative no-removal result.
- Invalid input → `TypeError`.
- Determinism (two runs identical, equal documents).
- Immutability (source untouched by identity and content; upstream objects
  shared by reference).
- Provenance (removed candidates link to the exact source paragraphs;
  document-order result lists).
- End-to-end integration: the real M2.7/M2.9 pipeline on a synthetic PDF
  whose `1, 2` sequence survives M2.5 (verified: `furniture.detected_count
  == 0`), removal works, chapters preserved, and the removed document flows
  through `reconstructed_document_to_book` → `build_epub` without the page
  numbers; the existing `convert_pdf_to_epub` path still works.

### 11. Known limitations

Intentionally conservative / not supported:

- Bare numbers are limited to 1–999 (`\d{1,3}`, M2.5's pattern); multi-page
  sequences of 4+-digit numbers are never removed. Roman numerals are not
  page-number forms.
- A **single** bare number, or a non-monotonic / positionally inconsistent
  bare-number set, is reported as a candidate but never removed — by design.
- Bare-number removal requires a monotonic sequence of ≥ 2 distinct values at
  a *consistent* edge; a real page-number system that alternates positions
  (e.g. mirrored left/right pages with different x but different y) is only
  removed when the normalized positions also agree within tolerance.
- Documents constructed without a `ParagraphLayout` have no page dimensions,
  so no geometry can be trusted: nothing is removed (no guesswork).
- Descending sequences are accepted when monotonic and positionally
  consistent (a documented, conservative extension); no other exotic
  numbering systems are handled.
- Explicit forms (`Page N`, `N / M`, `- N -`) at an edge are removed on the
  strength of form + geometry alone (no sequence required); a body-text
  mention such as "see Page 1" is preserved by the geometry filter.
