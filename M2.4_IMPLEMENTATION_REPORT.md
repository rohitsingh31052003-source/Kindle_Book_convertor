## 3. Public API added

From `kindle_converter.pdf`:

```python
classify_paragraphs(source: ParagraphPage | ParagraphLayout) -> HeadingPage | HeadingLayout
detect_headings(source: ParagraphPage | ParagraphLayout) -> HeadingPage | HeadingLayout
```

Data structures:

* `ClassifiedParagraph` — a preserved M2.3 paragraph plus `is_heading`,
  `score`, and `reasons`.
* `DetectedHeading` — a view of one paragraph classified as a heading.
* `HeadingPage` — one page's classified paragraphs in M2.3 order.
* `HeadingLayout` — the whole document's classified pages in page order.

All are immutable (`frozen=True`, `slots=True`) and reference the original
M2.3 `ReconstructedParagraph` objects without mutation.

## 4. Heading-detection algorithm implemented

The detector is a **conservative, multi-signal scoring model**. Each
paragraph is classified independently using typography, geometry, length,
and local context. No single signal is sufficient.

### Typography signals

* **Font size** relative to the page's prevailing body baseline (lower
  median of paragraph median font sizes). A paragraph whose median font
  size is ≥ `FONT_SIZE_RATIO_THRESHOLD` (1.25×) the baseline contributes
  positive evidence; ≥ `STRONG_FONT_SIZE_RATIO_THRESHOLD` (1.5×)
  contributes stronger evidence.
* **Bold typography** from `FontFlags.BOLD` combined with a weight-like
  font name (e.g. containing "Bold" or "Black"). A bare bold flag without
  a weight-like name is weaker evidence because PDF font flags describe
  *capability*, not usage.
* **Italic typography** from `FontFlags.ITALIC` or an italic-like font name.
* **Font-family change** relative to the page's dominant font family.
* **Mixed font-size contrast** within a paragraph (e.g. a drop cap).

### Geometry signals

* **Centered alignment** when the paragraph's left and right margins are
  roughly equal and it does not span most of the page width.
* **Large whitespace before/after** the paragraph, relative to the page's
  prevailing line height and the median gap between neighboring paragraphs.
* **Isolation** when the paragraph has large whitespace on both sides, or
  large whitespace on one side combined with another strong cue.
* **Page-edge proximity** as weak supporting evidence.

### Length signals

* **Short paragraph** (≤ `SHORT_PARAGRAPH_CHARS` = 80) contributes weak
  positive evidence.
* **Very short paragraph** (≤ `VERY_SHORT_PARAGRAPH_CHARS` = 30)
  contributes slightly stronger evidence.
* **Long paragraph** (> `LONG_PARAGRAPH_CHARS` = 180) is penalized as
  likely body content.

### Classification decision

A paragraph is classified as a heading only when it accumulates at least
`MIN_HEADING_SIGNALS` (2) distinct positive reasons *and* its total score
reaches `HEADING_SCORE_THRESHOLD` (2.5).

   font size alone does not define a heading.

## 11. Known limitations or concerns

* **Heuristic and layout-based.** M2.4 is explicitly *not* semantic NLP.
  It cannot determine whether text "sounds like" a heading. It relies
  entirely on typography, geometry, and local context.
* **False negatives are expected.** A heading that uses the same font size
  as body text (e.g. a bold-only heading) may not be detected if it lacks
  other supporting signals. This is intentional: false positives are more
  damaging than missing an occasional heading.
* **Page-local baseline.** The body baseline is computed per page. A page
  with only headings (e.g. a title page) has no body baseline to compare
  against, so headings on such pages may not be detected.
* **Font metadata may be missing.** When a PDF does not provide font
  size/name/flags, the detector degrades gracefully but loses typography
  evidence.
* **No cross-page reconstruction.** Each page is processed independently.
  A heading that spans a page boundary is not merged.
* **No EPUB integration.** M2.4 does not modify the EPUB generation
  pipeline. Integration with EPUB heading tags is a later milestone.
