# M2.13 — Image extraction and placement: implementation report

Status: implemented, all tests passing. No commit was made.

## 1. Summary

M2.13 adds a conservative V1 embedded-image layer: PyMuPDF image objects are
extracted once per distinct payload (SHA-256 dedupe), given deterministic
`image-NNN` ids, anchored per placement (page + bbox + order + xref), merged
with text by vertical position, converted to document `Image` blocks, and
packaged once per asset in EPUB (`EPUB/image-NNN.ext`).

## 4. Image model

Frozen/slots `ImageAsset(asset_id,data,mime,width,height,ext,xref,order)`,
`ImagePlacement(asset_id,page,bbox,order,xref)`,
`ImageExtractionResult(assets,placements,page_count)` in `pdf/images.py`;
`ReconstructedImage(placement,asset|None)` + `ReconstructedPage.images`
(default `()`) in reconstruction.py. Existing `document.Image` reused.

## 5. Extraction algorithm

Per page in order: unique xrefs from `get_images(full=True)` →
`extract_image(xref)` bytes/ext/dims → MIME via fixed table else magic sniff
→ SHA-256 dedupe → `get_image_rects` per xref sorted `(y0,x0,x1,y1)` → one
placement per rect. No OCR/vectors/rendering/text-to-image.

## 6. Identifiers

`image-001…` in first-appearance order; placement `order` is the global
sequence. No id()/UUID/time/address/path. SHA-256 is dedupe key only.

## 7. Multiple placements

Payload stored once; each rect/page is its own placement with own
page/bbox/order/xref. EPUB packages one resource per asset, reused by all

## 8. Placement/order

`placements` sorted `(page, order)`; text order (M2.2/M2.6→M2.3) untouched.
`ordered_body_elements(page)` merges text (first-line `y0`) and images (bbox
top); ties prefer text, then extraction order.

## 9. Reconstruction integration

`build_reconstructed_document(..., images=None)` attaches placements per page;
`None` = historical text-only output. `reconstruct_layout(..., images=None)`
threads it through. `reconstructed_document_to_book` emits `Image` blocks at
merged positions with `content_type` + `"<asset> p<page> xref<xref>"` alt text.

## 10. EPUB integration

First block per asset token claims `EPUB/image-NNN.ext`; repeats reuse it;
`_attach_images` packages each resource once. Legacy naming otherwise.
Verified via zip inspection + EbookLib reread.

## 11. Formats

Original encoding preserved; MIME from PyMuPDF `ext` else sniffing. No new
deps, no transcoding. Unsupported payloads raise existing `InvalidImageError`
at EPUB time, never silently dropped.

## 16. Limitations

- EPUB placement is flow order, not pixel-exact layout.
- No captions/figures/cover inference/transcoding.

split; EPUB dedupe via pipeline `image-NNN` alt-text token + legacy fallback.

failed bytes / empty payload → `ImageExtractionError`. Rect-less images keep
