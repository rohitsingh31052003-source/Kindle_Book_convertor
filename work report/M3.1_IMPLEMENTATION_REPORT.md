## 4. Architecture

### Page-level classification

Each page is classified using two deterministic signals:

1. **Meaningful text** (`has_meaningful_text`): Whether the page has a text line with at least `MEANINGFUL_TEXT_CHAR_THRESHOLD` (24) non-whitespace characters, and not all text lines are in the header/footer bands (`HEADER_FOOTER_BAND_FRACTION` = 0.15). This existing heuristic from M2 is reused.
2. **Image coverage** (`image_area_ratio`): Total image bounding box area divided by page area, computed from `page.get_image_info()` geometry.

Classification rules:
- **TEXT**: `has_meaningful_text=True` AND `image_area_ratio < IMAGE_AREA_RATIO_THRESHOLD`
- **SCANNED**: `has_meaningful_text=False` (regardless of image coverage)
- **MIXED**: `has_meaningful_text=True` AND `image_area_ratio >= IMAGE_AREA_RATIO_THRESHOLD`

### Document-level aggregation

`classify_pages()` derives document type from per-page `classification` fields:
- All pages TEXT -> TEXT
- All pages SCANNED -> SCANNED
- Any MIXED pages, or a mix of TEXT and SCANNED -> MIXED

This complements the existing `classify()` function (which uses the fraction of pages with meaningful text) and is available for later milestones that need page-classification-based routing.

### Meaningful-text detection

Reuses the existing M2 heuristic: longest non-whitespace line >= 24 characters AND not all lines in header/footer bands. This avoids classifying pages with only page numbers, headers, footers, or trivial fragments as text.

### Image coverage calculation

Uses `page.get_image_info()` to get image bounding boxes. Total image area is summed and divided by page area. Overlapping rects are counted separately (conservative upper bound). Ratio is clamped to [0.0, 1.0].

### Thresholds

| Constant | Value | Meaning |
|---|---|---|
| `MEANINGFUL_TEXT_CHAR_THRESHOLD` | 24 | Min non-whitespace chars in longest line for meaningful text |
| `HEADER_FOOTER_BAND_FRACTION` | 0.15 | Fraction of page height that is header/footer band |
| `TEXT_DOCUMENT_THRESHOLD` | 0.8 | Fraction of meaningful-text pages for TEXT doc type |
| `SCANNED_DOCUMENT_THRESHOLD` | 0.2 | Fraction of meaningful-text pages for SCANNED doc type |
| `IMAGE_AREA_RATIO_THRESHOLD` | 0.5 | Fraction of page area covered by images for image-dominated |

## 6. Classification Rules

### TEXT
A page containing meaningful native text and not dominated by scanned/image content (image coverage < 50% of page area).

### SCANNED
A page containing no meaningful native text. This includes:
- Full-page image pages
- Pages with only trivial text fragments (below 24-char threshold)
- Pages with only whitespace
- Empty pages (no text, no images)
- Pages with images but no meaningful text (regardless of image coverage)

### MIXED
A page containing meaningful native text together with significant image content (image coverage >= 50% of page area).

### Empty page behavior (explicitly defined)
Empty pages (no text, no images) are classified as SCANNED at the page level. At the document level, `analyze_pdf()` raises `NoContentError` because the document has no content anywhere. This is intentional: an empty document cannot be meaningfully classified.

## 10. Known Limitations

M3.1 intentionally does not solve:
- PDF page rendering (M3.2)
- OCR processing (M3.3)
- OCR cleanup (M3.4)
- Mixed-document OCR routing (M3.5)
- NLP-based classification
- LLM-based classification
- Any classification based on image content recognition (only geometry is used)

The `IMAGE_AREA_RATIO_THRESHOLD` of 0.5 is a heuristic that may need tuning against real-world PDFs. The current value works well for synthetic test PDFs but should be validated against production documents.
