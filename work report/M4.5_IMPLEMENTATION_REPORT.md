# M4.5 — Kindle-Specific Formatting Improvements Implementation Report

## 1. Summary

Implemented **M4.5 — Kindle-Specific Formatting Improvements**: the EPUB that
the builder already produced is now styled by one centralized, internal
Kindle formatting profile instead of scattered CSS literals, and the profile
is refined for reflowable Kindle reading:

- **Centralized profile.** `kindle_converter.epub.formatting` owns a small,
  frozen `KindleFormattingProfile` (body, paragraph, heading, chapter, image,
  blockquote, list, and page-break values) and a pure
  `build_stylesheet(profile)` function that renders the stylesheet
  deterministically. `builder.STYLESHEET_CSS` is that stylesheet for the
  default profile, so there is exactly one source of truth.
- **Reflowable typography.** Relative units only (`em`/`%`) — no `px`, `pt`,
  `in`, `cm`, `mm`, `vh`, `vw`; a conservative font stack ending in a generic
  family; no embedded or remote fonts, so the reader's font and font-size
  controls keep working.
- **Semantic formatting, unchanged structure.** Headings keep their
  `<h1>`–`<h6>` level, paragraphs stay `<p>`, images stay
  `<img class="image">`, a `PageBreak` stays an empty
  `div.page-break[aria-hidden]` with both a legacy and a modern break
  property. M4.5 styles what M1–M3 produced; it never re-derives structure,
  reading order, chapter splitting, or headings.
- **Improved reading details.** Conservative heading spacing with
  break-avoidance, no leading blank space in front of a chapter's opening
  heading, centered width-constrained images that preserve their aspect ratio,
  and conservative `blockquote`/`ul`/`ol`/`li` defaults for content that
  carries them.
- **Nothing device-specific.** One small stylesheet, prohibited fixed-layout
  constructs absent (verified by tests), no new dependency, no new public API,
  no JavaScript, no external resources, no `@media` device profiles, no
  KFX/fixed-layout/previewer work.

The architecture is unchanged:

```text
PDF/OCR/reconstruction ─► Book ─► Kindle-oriented EPUB builder ─► EPUB ─► (optional) AZW3
```

## 4. CSS architecture

One stylesheet, generated from one profile, packaged as `EPUB/style.css` and
linked from every chapter document and the cover page (the M4.1 mechanism is
unchanged). `formatting.py` holds:

```python
DEFAULT_FORMATTING = KindleFormattingProfile()   # frozen, immutable
STYLESHEET_CSS = build_stylesheet(DEFAULT_FORMATTING)   # builder.py
```

`build_stylesheet` is a pure function of the profile: it substitutes profile
values into a single `string.Template`, and the `h1`..`h6` size rules are
generated from `profile.heading_sizes` with equal adjacent sizes grouped
(`h1 { font-size: 1.6em; }`, …, `h4, h5, h6 { font-size: 1.1em; }`). The
result is one stylesheet of **1754 characters / 14 rules / 90 lines**, laid
out in readable sections in a fixed order:

| Section | Contents |
| --- | --- |
| Base / body | `html`, `body` — relative font size, line height, neutral margins, left alignment |
| Headings | shared `h1`–`h6` rule (weight, leading, spacing, break avoidance) + generated size rules |
| Chapters | `h1:first-child` … `h6:first-child` → `margin-top: 0` (no leading blank space) |
| Paragraphs | `p` — modest bottom margin, no indent, body leading |
| Images | `img.image` — responsive, centered, aspect-preserving, no splitting |
| Cover | comment only: the M4.4 cover page reuses `img.image`; no cover-specific or device-specific rule exists |
| Blockquotes | `blockquote` — em-based side/top/bottom margins, body leading |
| Lists | `ul, ol`, `li` — em-based indent, item spacing, no generated numbering |
| Page breaks | `div.page-break` — zero-height marker with legacy + modern break properties |

There is no second stylesheet, no per-chapter CSS, no per-element generated
class, and no `url()`/`@import`/`@media` dependency. The only class selectors
in the stylesheet are the two pre-existing hooks the markup uses
(`img.image`, `div.page-break`); a test enforces exactly that.
## 5. Typography

Body text (`body`):

```css
font-family: serif, Georgia, "Times New Roman", serif;
font-size: 1em;
line-height: 1.5;
text-align: left;
```

- Sizes are relative: `1em` for body text and `em`-based heading sizes, so a
  larger/smaller reader font scales the whole book without breaking layout.
- No font is forced and none is embedded; the stack ends in a generic family
  (`serif`) so the reading system's own font selection stays in control.
- Line height is 1.5 for prose and 1.3 for headings (tighter display leading).
- No fixed text width, no columns, no absolute positioning, no flexbox/grid
  for text, and no widow/orphan properties (they are not reliably supported
  by Kindle reading systems and were deliberately not added).
- Page margins stay entirely with the reading system; the stylesheet only
  controls block flow.

Paragraphs (`p`): semantic `<p>` per authored paragraph, `margin: 0 0 1em 0`
(a modest bottom margin, no top margin, no gap between wrapped lines),
`text-indent: 0`, `line-height: 1.5`. The builder adds no empty paragraphs and
no `<br>` layout substitutes (tests assert both), while an *authored* empty
paragraph still renders, preserving the M1.4 behavior covered by
`tests/test_epub_builder.py::TestParagraphs::test_empty_paragraph_renders`.

Headings: the M2/M3 levels are preserved exactly (`<h1>`…`<h6>`, deeper levels
still clamping to `<h6>`), with per-level relative sizes that decrease down the
hierarchy, `margin: 1.2em 0 0.5em 0` for space before/after, bold weight,
inherited family, and left alignment. No heading is flattened into a styled
paragraph, and no heading hierarchy is invented.

Chapters: one chapter per XHTML document, unchanged titles, order, spine, and
navigation. The M4.5 chapter refinement is that a heading which *opens* a
chapter carries no leading blank space (`h1:first-child` … `h6:first-child` →
`margin-top: 0`), so chapter starts are clean without fixed-height title
blocks or forced page breaks. Chapter splitting itself remains outside this
milestone (as in M4.1).

## 6. Page breaks

The M4.1/M3.6 page-break semantics are preserved exactly:

```html
<div class="page-break" aria-hidden="true" />
```

```css
div.page-break {
    height: 0; margin: 0; padding: 0;
    page-break-after: always;   /* legacy, for older readers */
    break-after: always;        /* modern counterpart */
}
```

- A `PageBreak` block still marks a *source page* boundary in reading order,
  rendered as a zero-height marker element (validated by M4.2 as an empty
  `div` with a defined stylesheet rule) rather than a fixed-size EPUB page.
- Breaks never appear before every paragraph and no break is emitted for
  visual PDF imitation: a three-page text PDF still yields exactly two
  markers, and a six-paragraph chapter yields none (tests assert both).
- Additional break control is conservative and only where it reduces awkward
  splitting when supported: `break-after: avoid` /
  `page-break-after: avoid` on headings, and `break-inside: avoid` /
  `page-break-inside: avoid` on headings, images, and list items. If a
  reading system ignores these properties, the book simply reflows.
- No forced break is inserted before chapters or sections, so the ebook can
  never behave like a fixed-layout PDF.

## 7. Images

Document images keep the M4.1 markup (`<img class="image" src="…" alt="…" />`)
with no `width`, `height`, or `style` attribute — a test enforces this — and
the stylesheet makes them responsive:

```css
img.image {
    display: block;
    max-width: 100%;
    height: auto;          /* aspect ratio preserved, never stretched */
    margin: 0.5em auto;    /* centered while it fits the reading width */
    page-break-inside: avoid;
    break-inside: avoid;
}
```

- Images scale *down* to the available reading width and never overflow it;
  they are never forced to fill the screen, never cropped, never upscaled, and
  never processed — the packaged bytes are compared against the source bytes
  in tests. No image-processing dependency was added.
- The M4.4 cover is unaffected and stays independent: it is packaged as
  before (`images/cover.<ext>`, `properties="cover-image"`, `name="cover"`
  metadata, `cover.xhtml` first in the spine, no navigation entry) and its
  page simply reuses `img.image`, so the cover has no fixed dimensions and no
  cover-specific CSS rule is needed (a test asserts the stylesheet defines no
  `cover` selector).
- Image captions are not styled because the document model has no caption
  element; no caption semantics were invented.
## 8. Semantic structure

| Domain block | XHTML | Markup change in M4.5 |
| --- | --- | --- |
| `Heading` | `<h1>`…`<h6>` (level preserved, `>6` clamps to `<h6>`) | none |
| `Paragraph` | `<p>` | none |
| `Image` | `<img class="image" src="…" alt="…">` | none |
| `PageBreak` | `<div class="page-break" aria-hidden="true" />` | none |
| `Chapter` | one XHTML document + navigation entry | none |

- Blockquotes and lists: the stylesheet defines conservative, semantic
  defaults for `blockquote`, `ul`, `ol`, and `li` (em-based margins, body
  leading, no generated content, no manual numbering, no `list-style`
  overrides). The current `Book` model has no blockquote or list blocks, and
  M4.5 does not invent any: a test asserts a plain paragraph book emits
  neither `<blockquote>` nor `<ul>`/`<ol>`/`<li>`. The domain model itself is
  unchanged (`DocumentBlock` still covers exactly `Heading`, `Paragraph`,
  `Image`, `PageBreak`; a test asserts that).
- Accessibility: `alt` behavior is unchanged (author/`alt_text` when the model
  provides it, empty otherwise so decorative images stay decorative), the
  page-break marker keeps `aria-hidden="true"`, no description is invented
  for arbitrary PDF images, and no wrapper elements (`<main>`, `<section>`,
  `<article>`) were introduced, since that would change existing EPUB
  structure without a need.
- Internal links are untouched: targets, `nav.xhtml`, and `toc.ncx` are
  identical to M4.4 output. No JavaScript, no event handlers, and no external
  references exist (tests scan every XHTML document for `<script`,
  `javascript:`, inline event attributes, and non-local `href`/`src`).

## 9. Compatibility

- **M4.4 cover handling remains intact.** Covered EPUBs keep the packaged
  `images/cover.<ext>` bytes, `properties="cover-image"`, the
  `name="cover"` metadata entry, the reflowable `cover.xhtml` page, spine
  order `["nav", "cover", *chapters]`, and no navigation entry. New tests
  re-assert all of it on M4.5 output, and the M4.4 suite still passes
  unchanged.
- **M4.3 AZW3 conversion remains intact.** `convert_epub_to_azw3`, the Calibre
  backend, and the subprocess contract were not touched. Because the M4.3
  integration layer builds its fixture EPUBs with the project's own
  `build_epub`, the optional real-Calibre tests now exercise M4.5 output:
  both the coverless and the covered conversion passed with local Calibre.
- **M4.2 validation remains intact.** `validate_epub` and its code set were
  not modified. Every M4.5-generated EPUB asserted in the new tests
  (coverless, covered, OCR, mixed, illustrated, text) validates with
  `result.valid` and `error_count == 0`. Validation is still a standalone,
  read-only step and is still not wired into conversion.
- **M1–M3 reconstruction remains intact.** No PDF, OCR, routing,
  reconstruction, metadata, or chapter module changed. The document model is
  untouched, so OCR and mixed books keep their existing content and source
  semantics (native text before OCR text, never merged) — verified through the
  real pipeline with a fake OCR engine.
- **Coverless EPUBs remain compatible.** A book without a cover produces no
  cover resource, no `name="cover"` metadata, and spine `["nav", *chapters]`,
  exactly as before; only the stylesheet content changed.
- **Existing APIs remain compatible.** `convert_pdf_to_book`,
  `convert_pdf_to_epub`, `build_epub`, `validate_epub`, and
  `convert_epub_to_azw3` keep their signatures and behavior; no positional or
  keyword parameter changed, and no import path was removed. `STYLESHEET_CSS`
  and `STYLESHEET_RESOURCE` still exist in
  `kindle_converter.epub.builder`.

## 11. CSS compliance

The generated stylesheet contains **none** of the prohibited constructs. The
compliance test does not naive-substring the CSS: comments are stripped, the
text is parsed into rules and declarations, and the checks run on parsed
property names, parsed `display` values, and unit-boundary regular
expressions, so a legitimate value can never cause a false positive.

| Prohibited construct | Status in generated CSS |
| --- | --- |
| `position: absolute` / `position: fixed` (and any `position`) | absent |
| `top`/`right`/`bottom`/`left`, `z-index`, `float`, `clear` | absent |
| `display: grid` / `display: flex` (any grid/flex display value) | absent |
| `gap`, `flex-*`, `align-*`, `justify-content`, `grid-*` | absent |
| CSS columns (`columns`, `column-*`) | absent |
| `px`, `pt`, `pc`, `cm`, `mm`, `in`, `vh`, `vw`, `vmin`, `vmax` | absent |
| `@media` (any at-rule), including any guessed Kindle dimension | absent |
| `@font-face` / remote or embedded fonts | absent |
| `@import` / second stylesheet / external stylesheet | absent |
| `url(...)` dependencies, external images | absent |
| JavaScript (`<script`, `javascript:`, inline event handlers) | absent |
| `animation`, `transition`, `transform` | absent |
| `expression(...)` (legacy script-in-CSS) | absent |

No exception is required for any existing feature: the two class hooks the
markup uses (`img.image`, `div.page-break`) are styled with ordinary
reflowable rules, and the page-break element is styled as a break marker
rather than a page box.

## 12. Determinism

- `KindleFormattingProfile` is frozen and `build_stylesheet` is a pure
  function of it, so the stylesheet is a value: no timestamps, no random
  UUIDs or addresses, no environment or timezone input, no generated
  per-element class names, and no iteration over unordered collections. Two
  calls return byte-identical CSS, and a test enforces it.
- The packaged `EPUB/style.css` is byte-identical to `build_stylesheet()`, and
  repeated builds of the same `Book` produce identical chapter/nav/cover
  XHTML and CSS (a test compares every `.xhtml`/`.css` member of two builds).
- The same stylesheet is packaged for native, OCR, and mixed books, and for
  coverless and covered books.
- Remaining nondeterminism is exactly the pre-existing, library-level one
  documented since M4.1: EbookLib stamps `dcterms:modified` and ZIP entry
  times into the container. M4.5 adds no new source of variation and makes no
  claim of complete byte-level EPUB determinism.

## 13. Known limitations

M4.5 deliberately does **not** provide:

- **Exact Kindle device rendering.** The styling is Kindle-friendly and
  reflowable; it is not a simulation of any Kindle model, screen size,
  orientation, font size, or margin setting, and it makes no pixel-matching
  claim against a physical device.
- **Fixed-layout output.** No fixed page or viewport dimensions, no absolute
  positioning, no PDF geometry reproduction.
- **Kindle Previewer validation.** No Kindle Previewer or KindleGen
  integration, and no device-emulation step.
- **KFX.** Not implemented, and no KFX tooling is invoked.
- **Device-specific CSS profiles.** No per-model stylesheets or media
  queries; there is exactly one stylesheet for all reading systems.
- **Advanced typography engines.** No hyphenation control, no font embedding,
  no optical margin alignment, no drop caps, and no widow/orphan tuning — all
  of which would either defeat reader-controlled settings or require
  unsupported Kindle CSS.
- **New formatting configuration.** The profile is internal: users cannot
  select themes (no public API was added), and no CLI/GUI option exists.
- **Structure changes.** Chapter splitting, heading detection, reading order,
  paragraph reconstruction, image extraction, page-break placement, and the
  `Book` domain model are untouched: chapter splitting is still one chapter
  per document, as documented for M4.1.
- **Content of quote/list/caption elements.** Because the model has no
  blockquote, list, or caption blocks, the corresponding CSS is inert for
  current output; the builder never fabricates such elements.
