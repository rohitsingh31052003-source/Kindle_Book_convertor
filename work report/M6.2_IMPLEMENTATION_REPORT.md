# M6.2 — Regression Test Harness — Implementation Report

## 1. Summary

M6.2 adds a **deterministic, corpus-driven regression harness**
(`tests/regression`) that runs every M6.1 representative fixture through the
**existing, unmodified** conversion pipeline and asserts observable,
structural behavior against a small version-controlled baseline
(`tests/fixtures/regression_baseline.json`). The purpose is to make future
changes fail loudly when they silently break classification, native /
scanned / mixed processing, reading order, paragraph reconstruction,
headings, chapters, TOC, image extraction and placement, EPUB generation, or
EPUB validation — without making harmless implementation refactors break the
suite.

Design highlights:

* **Corpus-driven, not hard-coded.** Test cases are discovered through the
  public M6.1 discovery API (`tests.fixtures.corpus.iter_documents` /
  `document_path`); per-fixture facts are read from `manifest.json` rather
  than duplicated in the tests.
* **Real pipeline, public APIs only.** The harness calls
  `analyze_pdf`, `extract_page_layout` / `reconstruct_layout` /
  `detect_chapters`, `convert_pdf_to_book`, `convert_pdf_to_epub`,
  `validate_epub`, and the M5 `ConversionApplication` — exactly what the
  desktop app calls. No converter module was modified, and no second
  conversion path exists.
* **Deterministic OCR.** A tiny injected engine (`CountingOCR`) records how
  many pages reach `recognize()` (the observable *routing* signal) and
  returns the predictable text `OCR-TEXT-FOR-CALL-<n>`. Scanned and mixed
  fixtures therefore exercise the genuine OCR routing **without Tesseract,
  Calibre, network, or a GUI**, keeping the default suite runnable in any
  development environment.
* **Semantic assertions only.** No byte-for-byte EPUB snapshots, ZIP member
  ordering, HTML formatting, or private-helper checks. The baseline records
  compact structural facts (block counts, heading texts, chapter counts,
  OCR-call counts, EPUB artifact structure, validation results) plus
  human-authored content anchors (`contains` / `excludes`).
* **Actionable failures.** Parametrized tests name the fixture (and often the
  fact / anchor) directly in the assertion message, so a failure reads e.g.
  `headers_footers: 'The Lantern Keeper' leaked into body text`.
* **`pytest -m regression`** selects exactly the M6.2 suite (253 tests) via a
  new marker in `pyproject.toml`; the plain `pytest` run includes it as part
  of the normal suite, per the repository convention.

Cross-cutting, applied to **all eleven fixtures** (parametrized):

* classification and page-count facts match both the corpus manifest and the
  frozen baseline (corpus drift is caught);
* OCR routing follows classification (TEXT → 0 calls; SCANNED/MIXED → > 0);
* block composition, heading texts, chapter count, EPUB numeric structure,
  and content anchors match the baseline;
* the generated EPUB always validates with 0 errors;
* fixtures the manifest declares as carrying images keep ≥ 1 image block and
  ≥ 1 packaged EPUB image resource;
* fixtures declaring `min_chapters` still detect at least that many.

## 6. Baseline / expectations

Regression expectations live in **`tests/fixtures/regression_baseline.json`**
(schema v1), deliberately separate from the corpus manifest:

* `manifest.json` stays the *corpus metadata* source of truth (what each
  fixture is, its declared features) and is shared with the future M6.3/M6.4
  consumers; it was not extended.
* The baseline holds the *pipeline behavior* facts M6.2 needs to freeze:
  analysis facts, block composition, OCR-call counts, heading texts, chapter
  counts, EPUB artifact structure and validation results — compact,
  human-readable JSON (≈ 420 lines for 11 fixtures), never an opaque EPUB
  snapshot.
* Semantic content anchors (`contains` / `excludes`) and the
  `twocolumn_article` `column_tokens` are **human-authored**: regeneration

* `pytest -m regression`: **253 passed**, 1637 deselected — 0 failed, 0
  errors, 0 skipped.
* `pytest` (full suite): **1884 passed, 5 skipped, 1 failed**.
* The 5 skips are the pre-existing optional Tesseract OCR integration tests
  (`tests/test_pdf_ocr_tesseract.py`), skipping cleanly with their documented
  message ("Tesseract executable not found…"). No M6.2 test skips.
* The 1 failure is `tests/test_corpus.py::test_regeneration_is_byte_identical`
  (`novel_basic`), a **pre-existing M6.1 issue unrelated to M6.2** — verified
  by running it in a clean worktree of the committed HEAD (`3651e8a`), where
  it fails identically. See §10.

## 9. Optional dependencies

* **Tesseract:** not required anywhere in M6.2. Scanned and mixed fixtures
  run with the injected `CountingOCR` engine; the baseline even asserts
  `"Tesseract"` / `"pytesseract"` never appear in converted output. The
  pre-existing optional Tesseract integration tests continue to skip
  independently.
* **Calibre:** untouched; the pre-existing AZW3/Calibre tests keep their own
  skip behavior. No M6.2 test needs it.
* **Network / GUI / clock:** none used — the harness is fully offline,
  headless, and wall-clock-free (temp dirs via `tempfile`, no timestamped
  assertions, relative corpus paths only).

## 10. Defects discovered

1. **Pre-existing (M6.1): fixture byte-determinism vs environment.**
   `tests/test_corpus.py::test_regeneration_is_byte_identical` fails on
   `novel_basic` under the current environment (pymupdf 1.28.2): the
   generator reproduces all bytes except one, at PDF object-stream offset 37
   (`b'8'` vs `b'7'`), i.e. an object/generation-number difference emitted by
   a different pymupdf build. This is **not** a converter defect and **not**
   caused by M6.2 (identical failure at committed HEAD in a clean worktree).
   It belongs to M6.1 follow-up: either regenerate/recommit the fixtures
   with the environment's pymupdf, or relax that single test to a structural
   (not byte) equality. Left unchanged here so M6.2 does not weaken M6.1
   coverage.
2. No converter defects were found by the regression matrix: all 11 fixtures
   convert, validate, route correctly, and match the corpus manifest.
