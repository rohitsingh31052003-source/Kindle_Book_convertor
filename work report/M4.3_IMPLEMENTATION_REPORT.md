# M4.3 — AZW3 Conversion Implementation Report

## 1. Summary

Implemented **M4.3 — AZW3 Conversion**: an explicit, standalone output step
that turns a finished EPUB artifact into an AZW3 (Kindle) ebook through
Calibre's `ebook-convert` command. The AZW3 layer consumes only the EPUB
artifact — never a PDF or `Book` — so the architectural boundary
`PDF/OCR/reconstruction → Book → EPUB → AZW3` is preserved, and the flow is
extended to:

```text
PDF
 ↓
Book
 ↓
EPUB
 ↓
AZW3
```

The AZW3 format is never implemented in Python. Calibre is an **optional,
external** system dependency: the package stays importable and the entire
EPUB stack keeps working without it. All subprocess/executable behavior is
isolated in one small adapter, and the core test suite exercises the
conversion engine through a stubbed subprocess and injected fake backends —
no Calibre required.

## 4. Architecture

The conversion layer is an explicit `EPUB → AZW3` step:

```text
Book → build_epub() → EPUB → convert_epub_to_azw3() → AZW3
```

- `convert_epub_to_azw3(source, destination, *, calibre_path=None)` consumes
  an EPUB **artifact** (a filesystem path). It imports no PDF/OCR code,
  performs no EPUB validation, and never chains automatically after
  `convert_pdf_to_epub`; callers compose the full chain when they need it.
- The high-level API depends on the small `AZW3ConversionBackend` protocol
  and never calls `subprocess.run` itself. The production `CalibreBackend`
  isolates every executable/subprocess concern: discovery, command
  construction, checked exit codes, and bounded error diagnostics.
- After the backend reports success, the API verifies the output artifact
  (exists, regular file, non-empty) and returns an immutable
  `AZW3ConversionResult`. The M4.3 validation guarantee is deliberately
  shallow: successful conversion + a non-empty artifact at the destination.
  It is not a Kindle-rendering-correctness guarantee.

## 5. Public API

```python
from kindle_converter.epub import (
    convert_epub_to_azw3,
    AZW3ConversionResult,
    AZW3ConversionBackend,
    AZW3ConversionError,
    AZW3BackendUnavailableError,
    AZW3ConversionFailedError,
    AZW3InvalidInputError,
    AZW3InvalidOutputError,
    CalibreBackend,
)
```

### `convert_epub_to_azw3(source, destination, *, calibre_path=None, backend=None)`

- Accepts an existing, readable `.epub` filesystem path for `source`.
- `destination` is the `.azw3` output path (parent must exist; existing file
  is overwritten).
- `calibre_path` overrides executable discovery; `backend` injects an
  `AZW3ConversionBackend` (used as-is, ignoring `calibre_path`).
- Returns `AZW3ConversionResult(source, destination)` after output
  verification.

### `AZW3ConversionResult`

Frozen, slotted dataclass: `source: Path`, `destination: Path`. Signals that
the backend finished successfully and the output artifact was verified.

## 6. Error handling

| Error | Meaning |
| --- | --- |
| `AZW3BackendUnavailableError` | `ebook-convert` cannot be found on `PATH`, a configured `calibre_path` does not exist, or the executable cannot be launched. |
| `AZW3ConversionFailedError` | Calibre ran but returned a non-zero exit code; the message carries source, destination, return code, and a bounded stderr/stdout excerpt (never the full output, never environment data). |
| `AZW3InvalidInputError` | The source is not a path, does not exist, is a directory, or is unreadable. |
| `AZW3InvalidOutputError` | Backend reported success but the output is missing, not a regular file, or empty. |

All are subclasses of `AZW3ConversionError`. Raw `FileNotFoundError` /
`OSError` / `CalledProcessError` are translated and never surface as the
public API.

## 8. Calibre integration

- **Executable discovery:** an explicit `calibre_path` (or
  `CalibreBackend(executable=...)`) is used as-is and its existence verified
  eagerly; otherwise `ebook-convert` is looked up on `PATH` via
  `shutil.which` at convert time. Works across Windows/Linux/macOS; no
  Windows-only path is hard-coded.
- **Subprocess behavior:** `subprocess.run([...], shell=False,
  capture_output=True, text=True, encoding="utf-8", errors="replace")` — no
  shell, paths stay separate arguments, stdout/stderr captured, non-zero
  exit raises `AZW3ConversionFailedError`.
- **Optional integration test:** discovers `ebook-convert` via the
  `CALIBRE_CONVERT` environment variable or `PATH`, skips when absent, and
  converts a small synthetic EPUB (built on the fly with `build_epub`) to
  AZW3, asserting the artifact exists and is non-empty. On this machine
  Calibre was installed, so the real conversion ran and passed.

## 9. Determinism

- **Deterministic:** command construction — the same executable, source, and
  destination always produce the same argument list
  (`build_calibre_command`), with no shell quoting, timestamps, temporary
  filenames, or environment-dependent flags.
- **Not deterministic:** the AZW3 byte content. Calibre may stamp its own
  metadata and timestamps into the artifact, and that is explicitly accepted
  and documented for M4.3.

## 10. Compatibility

- Existing EPUB generation is unchanged; no automatic EPUB → AZW3 chaining
  was added to `convert_pdf_to_epub` / `convert_pdf_to_book`.
- EPUB validation remains a separate, standalone step.
- PDF/OCR/reconstruction layers (M1–M3) are untouched.
- Calibre is optional: `import kindle_converter` and all EPUB functionality
  work without it.

## 11. Known limitations

This milestone does **not** provide:

- Kindle rendering validation (compatibility proof for Kindle devices),
- KFX conversion,
- MOBI conversion,
- Kindle Previewer automation,
- Amazon marketplace validation,
- advanced Kindle-specific formatting,
- AZW3 repair/parsing, or
- cover handling beyond whatever the existing EPUB already contains.
