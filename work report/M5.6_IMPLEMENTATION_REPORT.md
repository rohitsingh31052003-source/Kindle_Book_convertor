# M5.6 — Results + Validation — Implementation Report

## 1. Summary

M5.6 completes the post-conversion experience of the desktop workflow. After a
background conversion succeeds, the main window presents a **results section**
built exclusively from the real application-layer `ConversionResult` that the
M5.5 worker delivered (status, output format derived from `requested_formats`,
and the exact `epub_path` / `azw3_path`) and, when the result carries one, a
**validation section** rendering the existing `EPUBValidationResult`
(valid / invalid, warning / error counts, and the structured
`EPUBValidationIssue` messages), with "Not run" for a result whose validation
was disabled. The UI never reruns validation, and no second, UI-specific result
model exists. Three output actions — **Open EPUB**, **Open AZW3**, **Open
Folder** — open the real output paths through an injectable platform seam
(`kindle_converter.ui.platform.open_path`, which translates platform failures
into a single `PlatformOpenError`); missing results, missing outputs, and
failed opens are reported locally and never crash the window or modify the
result. Stale results are protected: any input, output-format, or
output-directory change, and the start of any new conversion, clears a previous
result, so an old result is never presented as the current request's. The core
library still never imports PySide6, and `worker.py` was not touched.

## 4. Architecture

```text
M5.5 worker delivers the real ConversionResult on the GUI thread
                     │
                     ▼
  _on_conversion_succeeded(result)
      │  last_result = result (verbatim, retained)
      │  _populate_results(result)          ── read-only, no recomputation
      │      ├─ result status label          = "Conversion complete"
      │      ├─ format label                 = _result_format_label(result)
      │      │                                  ("EPUB" or "EPUB + AZW3" from
      │      │                                   result.requested_formats)
      │      ├─ epubOutputPath               = str(result.epub_path)
      │      ├─ azw3 row/button              = visible ⇔ result.azw3_path is not None
      │      └─ _populate_validation(result.validation)   (never rerun)
      │              ├─ validation is None   → "Not run"
      │              ├─ validation.valid     → "Valid" / "Invalid"
      │              ├─ warning/error counts → str(validation.warning_count/error_count)
      │              └─ bullet-list details  → "• <issue.message>" per warning/error issue
      │
      ▼
  Output actions (GUI thread, injectable opener)
      open_epub   → _open_output(result.epub_path)
      open_azw3   → _open_output(result.azw3_path)
      open_folder → _open_output(result.epub_path.parent)
          │  None result      → "No output is available to open."
          │  path missing     → "The output is no longer available: <path>"
          │  opener raises
          │    PlatformOpenError / OSError → "Could not open <path>: <err>"
          │  otherwise         → opener(Path(path))   [default = ui.platform.open_path]
          ▼
  open_path(path): os.startfile / ["open", ...] / ["xdg-open", ...]
      wraps FileNotFoundError/OSError into PlatformOpenError
```

Stale-result protection (`_clear_result`): `_conversion_result = None` and the
whole results section is hidden whenever the current request is invalidated —
`select_input`, `convert_selected` (before starting the new worker), and
`_refresh_configuration` (output-format / output-directory / cover changes).

## 5. Platform seam

`src/kindle_converter/ui/platform.py`:

- `open_path(path: Path) -> None` dispatches by `sys.platform`:
  `os.startfile(str(path))` on Windows, `subprocess.Popen(["open", str(path)])`
  on macOS, `subprocess.Popen(["xdg-open", str(path)])` elsewhere. All
  `FileNotFoundError` / `OSError` failures are translated into
  `PlatformOpenError`; existence is deliberately *not* asserted here (the
  window checks so it can show the precise "no longer available" message).
- `MainWindow.__init__(..., opener=None)` defaults to `open_path`; tests inject
  a recording double, so UI tests verify the exact path an action would open
  without launching a real application.
- The seam lives in the UI layer, is pure Python, and is small enough to be
  replaced wholesale — the core conversion domain still never launches external
  programs.

## 6. UI behavior

- **Results are hidden until a success.** The section is `setVisible(False)`
  at construction; only `_populate_results` makes it visible. A failed
  conversion therefore never displays a successful result.
- **Every displayed value is read from the retained real result.** Status,
  requested output formats, `epub_path` / `azw3_path`, and the
  `EPUBValidationResult` are taken from `last_result`; nothing is recomputed,
  rerun, or reconstructed (no second result model).
- **Output actions never modify the result.** Opening reads only;
  `_conversion_result` is unchanged and output files on disk are untouched.
- **Window stays usable.** Output-action failures surface on a local status
  label in the results section; the window remains in `COMPLETED` and all
  controls stay enabled.

## 7. Tests

- `python -m pytest tests/test_ui_platform.py` — **12 passed**. Per-branch
  `open_path` behavior on Windows / macOS / Linux using recording doubles for
  `os.startfile` and `subprocess.Popen` plus monkeypatched `sys.platform`;
  `PlatformOpenError` translation for `OSError` and `FileNotFoundError`
  (errno-2 maps to `FileNotFoundError`, so a distinct errno exercises the
  plain `OSError` branch); the no-existence-contract; no raw OS exceptions leak.
- `python -m pytest tests/test_ui_conversion_results.py` — **31 passed**
  (stable across repeated runs). Drives the real M5.5 `QThread` lifecycle with
  an injectable fake application (as in M5.5) and a recording opener.
  - **Results visibility:** no presentation before a successful conversion;
    completion shows it; failure never shows a result; window usable after.
  - **Results presentation:** EPUB-only and EPUB + AZW3 displays; output paths
    come from the real retained `ConversionResult` (object identity of
    `last_result.request`); a subsequent conversion replaces the previous
    result.
  - **Validation presentation:** valid / warnings / invalid / "Not run";
    counts and bullet messages come from the existing
    `EPUBValidationResult` objects; the UI performs the single pre-flight
    validation and the single conversion, and rendering the result adds **no**
    further validation calls (plus a source-scan test that `"validate_epub"`
    does not appear in `main_window.py`).
  - **Stale results:** cleared on input change, output-format change,
    output-directory change, and at the start of a new conversion; retry after
    failure shows only the fresh result.
  - **Output actions:** correct path sent to the opener for EPUB / AZW3 /
    folder; missing output and `PlatformOpenError` handled locally without
    touching `last_result`; opening a file or folder leaves the retained
    `ConversionResult` and the on-disk outputs unchanged.
- Full suite: `python -m pytest` — **1503 passed, 5 skipped** (baseline before
  M5.6: 1467 passed, 5 skipped; before M5.5: 1429 passed). The 5 skips are the
  pre-existing optional Calibre integration tests; unchanged.

## 9. Design decisions

1. **Real result only; no second model.** The results section reads
   `last_result` (the verbatim M5.5 `ConversionResult`). Display values are
   derived from real result fields (`requested_formats`, `epub_path`,
   `azw3_path`, `validation`) and `EPUBValidationResult` fields (`valid`,
   `warning_count`, `error_count`, `warnings`/`errors` issue lists).
2. **Never rerun validation.** `result.validation` is exactly the result the
   worker already produced inside `ConversionApplication.convert`; the UI only
   renders it. This is enforced by both a behavioral test (validation call
   count is unchanged by presentation) and a source-scan test.
3. **Inject the platform opener.** The default `open_path` uses
   `os.startfile` / `open` / `xdg-open`, but `MainWindow` accepts an injectable
   `opener`, so UI tests verify the *exact path* sent to the platform layer
   with zero real launches; the seam is unit-tested separately per platform
   branch.
4. **Clear, never race.** `_clear_result()` runs synchronously on the GUI
   thread at every invalidation point (new input, option change, start of a
   conversion) so a stale result can never be presented; no async coordination
   is required.
5. **Deterministic visibility in tests.** The headless tests `show()` the
   window before asserting widget visibility (offscreen QPA); without `show()`
   every widget would report `isVisible() == False`.
6. **Deliberately no-op AZW3 presentation when absent.** The AZW3 row, its
   value, and the "Open AZW3" button are hidden unless the result carries an
   `azw3_path`, so the UI never implies an artifact that was not produced.
7. **`PlatformOpenError` is the only platform boundary.** Raw `OSError` /
   `FileNotFoundError` never reach the UI; the window additionally tolerates
   `OSError` from injected openers, so even a non-cooperating opener cannot
   crash the window.

## 10. Known limitations

- Error reporting beyond the local output-action status is deferred to M5.7
  (full errors + temporary-file cleanup architecture).
- "Output directory management" (reveal / manage from the window) remains a
  future Milestone-5 item; M5.6's **Open Folder** action already opens the
  real containing directory of the produced outputs.
- Opening uses the OS default handler only; no in-app preview or reader.
