## 4. Architecture Validation

- All M2 modules exist under `src/kindle_converter/pdf/` with models in
  `pdf/models.py` and document models in `document/models.py`.
- The pipeline (`pipeline.py`, `analyzer.py`, `extractor.py`) composes layout,
  reconstruction, headings, furniture filtering, chapters, and metadata into
  `extract_book` → `convert_pdf_to_epub`.
- `remove_page_numbers`, `generate_toc`, `extract_pdf_images`, and
  `resolve_metadata` are **explicit** APIs by design; the pipeline remains
  compatible and the M2.14 tests exercise each explicitly. This intentional
  architecture was preserved (no auto-wiring added).

## 19. Known Limitations

- `remove_page_numbers`, `generate_toc`, `resolve_metadata`, and
  `extract_pdf_images` remain explicit APIs (by design); the default
  `extract_book`/`convert_pdf_to_epub` path does not auto-apply page-number
  removal or TOC generation.
- Image placement in reconstruction appends images to their source page's
  element flow rather than interleaving mid-paragraph (documented M2.13
  design).
- Heading/chapter detection relies on typographic evidence only (M3's OCR
  path is out of scope).
