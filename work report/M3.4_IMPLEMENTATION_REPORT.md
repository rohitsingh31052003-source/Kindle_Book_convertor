# M3.4 Implementation Report - OCR Cleanup

## 1. Summary

Implemented M3.4: a **deterministic, conservative OCR text cleanup layer**
that transforms raw OCR output into stable, artifact-free text without ever
attempting to "correct" recognition.

```text
RenderedPage
     │
     ▼
 OCR engine        (ocr.py, M3.3 — raw recognized text, no cleanup)
     │
     ▼
 OCRResult
     │
     ▼
 OCR cleanup       (ocr_cleanup.py, M3.4 — conservative text cleanup)
     │
     ▼
 CleanedOCRResult
```

Key additions:

- **`clean_ocr_text(text) -> str`** - the deterministic, idempotent text
  pipeline: input validation -> Unicode NFC -> newline normalization ->
  control-character removal -> trailing line-whitespace removal ->
  pathological blank-line collapse -> document-edge trim.
- **`clean_ocr_result(result) -> CleanedOCRResult`** - per-page adapter over
  the M3.3 `OCRResult`, preserving the 1-based page number and returning a
  new immutable `CleanedOCRResult` (the source `OCRResult` is never mutated).
- **`clean_ocr_pages(results)`** - lazy, order-preserving multi-page iterator
  cleaning each result independently (pages are never merged).
- **`CleanedOCRResult`** - frozen/slots value object
  (`page_number: int`, `text: str`).
- **`MAX_CONSECUTIVE_BLANK_LINES = 2`** - the single named cleanup threshold.
- **105 deterministic unit tests** using known OCR strings only (no OCR
  engine, no PDF rendering).

The cleanup layer is strictly post-OCR: it does not know how Tesseract works,
does not render PDFs, does not call an OCR engine, and performs no structural
reconstruction or recognition correction.

## 4. Architecture

### Module location

`src/kindle_converter/pdf/ocr_cleanup.py`, following the package convention of
one focused submodule per milestone (`ocr.py`, `renderer.py`, `analyzer.py`,
...). Cleanup is deliberately **not** placed inside `ocr.py`, `renderer.py`,
or `extractor.py`.

### Relationship to M3.3

`ocr.py` owns OCR execution and returns raw `OCRResult` values (unchanged).
`ocr_cleanup.py` consumes those `OCRResult` values; it imports only
`OCRResult` from `.ocr` (for typing/validation) and performs no OCR work
itself. The M3.3 `TesseractEngine` is untouched and continues to return raw
engine output.

### Result representation

`CleanedOCRResult` is a `@dataclass(frozen=True, slots=True)` value object
mirroring `OCRResult`'s shape:

```python
@dataclass(frozen=True, slots=True)
class CleanedOCRResult:
    page_number: int
    text: str
```

`OCRResult` itself was **not** changed; the cleanup transformation is explicit
(`OCRResult -> CleanedOCRResult`) and the source result is never mutated.

### Per-text and per-page

Both are provided because each has a distinct, useful role:

- **Per-text** (`clean_ocr_text`) - the pure, independently testable
  primitive over a raw OCR string.
- **Per-page** (`clean_ocr_result`) - the typed adapter over one `OCRResult`,
  preserving the page number and delegating to the primitive.
- **Multi-page** (`clean_ocr_pages`) - a lazy sequential iterator over many
  results, preserving order and page numbers and never merging pages.

### Why this architecture

The existing M3.3 `OCRResult` is already a per-page frozen value object, and
the M2 reconstruction layers consume per-page text representations. A per-page
cleanup result with a preserved page number integrates with that stream
without introducing a paragraph/heading/line model early (structural
reconstruction is explicitly out of scope for M3.4). A document-level
text-concatenation API was deliberately **not** created.

### Why no reuse of existing M2 normalization

Repository inspection found **no generic document-cleanup module**. The only
"normalization" helpers that exist are comparison keys, not output cleanup:

- `header_footer._normalize_text` / `chapters._normalize_text` - NFKC +
  whitespace-collapse + `casefold` keys used **only** to compare repeated
  text; NFKC/casefolding would corrupt meaningful typography if applied to
  preserved output text.
- `extractor._normalize_line` - per-line normalization for native text
  extraction (collapses all internal whitespace); that aggressively collapses
  spacing and is part of M2 native-text extraction, not a document cleanup
  policy for OCR, whose line structure must be preserved.

Reusing either would have violated the conservative whitespace policy. M3.4
therefore implements OCR-specific cleanup in its own focused module, reusing
only the Python standard library (`unicodedata`, `dataclasses`,
`collections.abc`).

## 5. Cleanup Rules

The complete pipeline, documented in the module docstring, is (in order):

1. **Input validation** - `text` must be a `str` (not `None`, `bytes`,
   numbers, etc.); non-strings raise `TypeError`. This guarantees no
   `None`/wrong-type value can silently become `"None"`.
2. **Unicode NFC normalization** -
   `unicodedata.normalize("NFC", text)`. Canonical composition only: NFC was
   chosen because it is conservative and matches meaningful typography.
   **NFKC is deliberately not used** so compatibility characters (fullwidth
   forms, ligatures, circled digits, roman numerals) are never decomposed to
   ASCII.
3. **Newline normalization** - every `\r\n` and lone `\r` becomes `\n`.
   Meaningful line boundaries are preserved; lines are never joined.
4. **Control-character removal** - every Unicode `Cc`-category character is
   removed **except** `\n` and `\t` (named
   `_CONTROL_CHARACTER_EXCEPTIONS`). This removes NUL, C0 controls, DEL, and
   the C1 range (U+0080..U+009F) while keeping normal whitespace and all
   meaningful Unicode characters.
5. **Trailing line whitespace** - spaces and tabs are removed from the end of
   every line (`line.rstrip(" \t")`). Only space/tab are targeted
   (`_TRAILING_LINE_WHITESPACE`), so meaningful typographic whitespace
   elsewhere (e.g. NBSP) is never touched. Intentional internal spacing and
   indentation are preserved.
6. **Blank-line collapse** - runs of blank lines longer than
   `MAX_CONSECUTIVE_BLANK_LINES` (2) are reduced to that maximum. A blank
   line is any line with no non-whitespace characters, so space-only lines
   produced by OCR count as blank. Ordinary paragraph separation (up to the
   maximum) is preserved; paragraph boundaries are never collapsed away
   entirely.
7. **Document-edge trim** - leading/trailing whitespace of the whole result
   is removed (`text.strip()`). Indentation **inside** the document is
   preserved.

### Anything explicitly deferred

- **Hyphenation repair / line joining** - not implemented. Without layout
  context, `conver-`/`sion` cannot be distinguished from `well-`/`known`;
  line boundaries are preserved so the structural reconstruction layer can
  later use layout context.
- **Repeated header/footer removal, page-number removal, running-title
  removal** - deferred. These require page-level and document-level
  analysis, which is outside a text cleanup pass. (The project already owns
  deterministic M2 mechanisms in `header_footer.py` / `page_numbers.py` for
  the native-text path; M3.4 does not duplicate them.)
- **Ligature substitution** - deferred (requires language/context evidence).
- **Recognition correction** - explicitly out of scope (see next section).

## 6. Content-Preservation Policy

The cleanup layer removes or normalizes predictable OCR artifacts only. It
**never** guesses what the source document probably said. Specifically it does
not implement:

- spelling correction (`teh` is kept as `teh`);
- dictionary or corpus corrections;
- OCR character substitution / lookalike guessing (`0` is never changed to
  `O`, `1` to `I`, `5` to `S`, `rn` to `m`);
- grammar correction;
- semantic rewriting;
- language-model / LLM / cloud correction.

All of these require contextual evidence and are recognition corrections, not
cleanup. Content is preserved: meaningful text, punctuation, numbers,
URLs/emails, Unicode characters, compatibility characters, and internal
spacing/indentation survive unchanged when they do not match a targeted
artifact.

## 7. Idempotence

Every transformation is a fixed point of its own output, so the whole pipeline
satisfies the required invariant:

```text
clean(clean(text)) == clean(text)
```

Proof sketch:

- NFC is idempotent (NFC is a canonical fixed point).
- Newline normalization leaves no `\r`/`\r\n` to convert on a second pass.
- Control-character removal leaves no `Cc` characters (except the exempt
  `\n`/`\t`, which it keeps) to remove again.
- Trailing-line-whitespace removal guarantees no line ends in space/tab, and
  produces empty lines only for whitespace-only input lines.
- Blank-line collapse guarantees no run exceeds the maximum; re-collapsing
  keeps runs at the maximum.
- Document-edge trim guarantees no leading/trailing whitespace remains; it
  does not re-introduce any, so a second trim is a no-op.

Tests prove this for representative cases (parameterized over a dirty-text
matrix) at the text level, the single-result level (cleaned text is a fixed
point of `clean_ocr_text`), and the multi-page level.

## 8. Public API

Exported from `kindle_converter.pdf` (`__all__`):

| Kind | Name | Purpose |
|---|---|---|
| Type | `CleanedOCRResult` | Frozen value object: `page_number: int`, `text: str` |
| Function | `clean_ocr_text(text) -> str` | Deterministic, idempotent text cleanup pipeline |
| Function | `clean_ocr_result(result) -> CleanedOCRResult` | Clean one `OCRResult`, preserving its page number |
| Function | `clean_ocr_pages(results) -> Iterator[CleanedOCRResult]` | Lazy sequential multi-page cleanup |
| Constant | `MAX_CONSECUTIVE_BLANK_LINES` | `2` - the blank-line-run cap (named, centralized) |

Internal helpers (`_clean_text`, `_normalize_newlines`,
`_remove_control_characters`, `_strip_trailing_line_whitespace`,
`_collapse_blank_lines`, `_validate_result`, plus the private constants
`_CONTROL_CHARACTER_EXCEPTIONS`, `_TRAILING_LINE_WHITESPACE`) are
intentionally **not** exported (asserted by a test).

Error handling: `TypeError` for non-`str` text and non-`OCRResult` results;
`ValueError` for invalid page numbers (non-`int`, `bool`, or `< 1`, following
the project's 1-based page-number convention). No dedicated `OCRCleanupError`
was introduced: cleanup is pure string processing with no runtime failure
mode, so the package's existing `TypeError`/`ValueError` argument-validation
style is sufficient.

## 9. Tests

`tests/test_pdf_ocr_cleanup.py` - **105 deterministic tests** operating on
known OCR strings. No Tesseract, no pytesseract/Pillow, no PDF rendering.

Categories:

- **`CleanedOCRResult` representation** - fields, frozen/slots, equality,
  repr, unrelated-type inequality.
- **Newlines** - CRLF -> LF, CR -> LF, existing LF unchanged, mixed styles,
  no double-normalization of CRLF+Lone LF, boundaries preserved.
- **Unicode** - NFC composition applied, already-normalized unchanged,
  canonically-equivalent inputs agree, meaningful Unicode (Cyrillic, CJK,
  Greek, emoji) preserved, **no compatibility conversion** (fullwidth /
  ligature / circled / roman numerals stay unchanged).
- **Control characters** - NUL removal, C0/DEL/C1 removal, tabs preserved,
  newlines preserved, control runs removed, meaningful chars untouched.
- **Whitespace** - trailing spaces/tabs removed, document-edge whitespace
  removed, internal spaces preserved, indentation preserved, whitespace-only
  line becomes blank, pathological blank runs collapsed (including the exact
  spec example `paragraph\n\n\n \n \n \nparagraph`), normal paragraph
  separation preserved, `MAX_CONSECUTIVE_BLANK_LINES` cap verified.
- **Safety/content preservation** - empty string, whitespace-only string,
  normal prose, punctuation, numbers, URLs/emails, non-ASCII, quotes/dashes,
  legitimate repeated spaces preserved, no OCR character substitution, no
  dehyphenation (`conver-`/`sion` and `well-`/`known` untouched).
- **Idempotence** - `clean(clean(x)) == clean(x)` over a dirty-text matrix;
  result-level and multi-page-level idempotence.
- **Determinism** - same input -> identical output, and a fixed exact expected
  output for a representative dirty OCR string.
- **Result-level API** - page-number preservation, text delegation to
  `clean_ocr_text`, source `OCRResult` never mutated, immutability,
  non-`OCRResult` inputs rejected, invalid page numbers rejected.
- **Multi-page API** - order/page-numbers preserved, pages cleaned
  independently, pages never merged, generator input, laziness, non-iterable
  rejected, bad element rejected, no cross-page concatenation.
- **Public API** - exports present in `__all__`, internal helpers absent from
  `__all__` but importable, constant value, `OCRResult` still exported.

## 13. Known Limitations

M3.4 implements only conservative, deterministic OCR **cleanup**. It
explicitly does **not** implement:

- spelling correction;
- OCR character / lookalike correction (`0->O`, `1->I`, `rn->m`, ...);
- dictionary correction;
- dehyphenation / line joining based on semantic inference;
- ligature substitution;
- repeated-header/footer removal;
- page-number removal / running-title removal;
- paragraph reconstruction;
- heading detection;
- mixed-document OCR routing (M3.5).

The cleaned text preserves line structure and internal spacing/indentation by
design, so later structural reconstruction can operate on stable per-page
text without having to re-derive lost boundaries.
