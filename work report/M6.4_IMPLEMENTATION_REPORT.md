# M6.4 Implementation Report

## 1. Summary

M6.4 adds a reproducible performance framework over the existing M6.1 corpus.
It measures real PDF-to-EPUB conversion stages, repeated-run timing, peak
Python allocations, environment metadata, baseline comparison, and explicit
baseline regeneration. Production conversion code was not changed.

## 2. Benchmark architecture

`tests/performance/harness.py` discovers fixtures from
`tests/fixtures/corpus/manifest.json`, uses the public `analyze_pdf`,
`convert_pdf_to_book`, `build_epub`, and `validate_epub` APIs, and writes each
run to a fresh temporary directory. Scanned and mixed fixtures use the M6.2
`CountingOCR` test double. `tests/performance/report.py` renders machine and
human reports; `regenerate_baseline.py` provides preview-only and explicit
write modes.

## 3. Benchmark protocol

The committed baseline uses one warm-up and three measured runs per fixture.
Each measured run starts from fresh conversion state and output storage.
`time.perf_counter()` supplies monotonic elapsed timing; medians are used for
comparison while minimum, maximum, and rounded samples remain available.
Phase timings cover PDF analysis, Book conversion, EPUB generation, and EPUB
validation. `tracemalloc` records peak Python allocation bytes per fixture;
this is not process RSS or total system memory.

## 4. Corpus coverage

All 11 manifest fixtures participate: `novel_basic`, `textbook_dense`,
`twocolumn_article`, `scanned_book`, `text_with_images`, `headers_footers`,
`unusual_typography`, `mixed_text_image`, `chapters_long`,
`edge_interleaved_blank`, and `edge_short_report`.

## 5. Performance baseline

`tests/fixtures/performance_baseline.json` is schema version 1 and is
independent from the M6.2 regression and M6.3 quality baselines. It stores
fixture metadata, elapsed statistics, phase statistics, allocation peaks,
protocol details, tolerance, and Python/platform/dependency context.
Comparison reports expose baseline, observed, delta, threshold, and status.
The default relative tolerance is 25%, chosen to avoid treating ordinary
local timing noise as a regression while still identifying material changes.

Preview and explicit regeneration:

```text
python -m tests.performance.regenerate_baseline
python -m tests.performance.regenerate_baseline --write
```

## 7. Phase analysis

`book_conversion` has the largest median among the four measured phases for
all 11 fixtures. It includes the converter's extraction, reconstruction,
image handling, and deterministic OCR routing. The SCANNED and MIXED fixtures
are substantially slower than native-text fixtures, consistent with their
render/OCR work. EPUB generation and validation are smaller phases in this
corpus.

## 8. Optimizations

No production optimization was made. The measurements identify conversion and
OCR routing as the dominant cost, but M6.4 does not provide a safe,
non-semantic optimization supported by enough evidence to justify changing
those paths. Leaving behavior unchanged preserves M6.2 and M6.3 contracts.

## 10. Memory

Memory is measured with standard-library `tracemalloc` around measured runs.
The stored metric is `python_tracemalloc_peak_bytes`; it excludes native
allocator/process RSS and operating-system memory used by PyMuPDF or external
OCR processes. It is therefore useful for Python allocation comparisons, not
a claim about total application memory.

## 11. Determinism and environment

Corpus discovery, OCR text routing, fixture inputs, run counts, aggregation,
and report schema are deterministic. Wall-clock performance and allocation
measurements naturally vary by machine and dependency/runtime versions.
The baseline records Python, OS/platform, machine architecture, PyMuPDF, and
ebooklib versions for interpretation. Tesseract, Calibre, network access, and
optional extras are not required.

## 14. Optional dependencies

None. The default benchmark and tests use existing project dependencies and
Python standard-library timing, metadata, and allocation tools.

## 15. Known limitations

The benchmark reports deterministic injected-OCR routing, not real Tesseract
performance. `tracemalloc` is not RSS. Absolute timings are environment
dependent, and the phase decomposition measures the same public stages
without invasive production instrumentation; temporary-directory cleanup and
benchmark reporting are outside the phase timings.

## 16. M1–M5 impact

No production conversion behavior or public conversion API changed. M6.4
only adds test/benchmark infrastructure and documentation.
