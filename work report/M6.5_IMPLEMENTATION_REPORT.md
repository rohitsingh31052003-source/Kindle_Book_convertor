# M6.5 Implementation Report

## 1. Summary

M6.5 packages the desktop application as a reproducible Windows artifact and
verifies that artifact from a process that never imports the project's Python
packages (the "clean-machine" check). The result is a PyInstaller **onedir**
bundle `dist/KindleBookConverter/` containing a single GUI-subsystem
executable, the real runtime distributions, and a Windows version resource,
plus build/verification tooling under `build_tools/` and a headless smoke
harness that ships inside the artifact. No production conversion logic was
changed; two harmless seams (`ui/app.main` argument dispatch and the
`ui/smoke` module) were added for verification.

## 2. Build architecture

`build_tools/build_windows.py` creates a project-dedicated virtual
environment (`build/windows_build_venv`, Python 3.14.2), installs
`.[ui,ocr] pyinstaller` (PyInstaller 6.22.3), generates
`build/version_info.txt` from `pyproject.toml` in the canonical
version-resource format, runs PyInstaller (`dist`/`build/pyinstaller`), and
strips provenance (`INSTALLER`, `direct_url.json`) from every bundled
`*.dist-info` so no development absolute path leaks into the artifact.
`--keep-venv` preserves the packaging venv between rebuilds.

The freeze graph (`build_tools/KindleBookConverter.spec`):

* entry `build_tools/windows_entry.py` -- a plain absolute-import script,
  because the frozen runtime cannot reproduce the relative-import semantics
  of `python -m` (`ui/__main__.py:7` raised "attempted relative import with
  no known parent package" frozen);
* `console=False` -- a single GUI-subsystem executable; the windowed
  bootloader detaches stdout, so verification uses `--report <path>` files
  and the exit code as the primary signal;
* `copy_metadata` for `kindle-converter`, `PySide6`, `PyMuPDF`, `ebooklib`,
  `lxml`, `Pillow`, and `pytesseract` -- frozen `importlib.metadata.version`
  resolves real versions and the `*.dist-info` directories give the verifier
  a filesystem-level proof that each pure-python distribution was frozen;
* `hiddenimports` for `kindle_converter.ui.smoke`, `pytesseract`, `PIL`,
  `PIL.Image` (the OCR layer imports them lazily);
* a Windows version resource carrying `0.1.0` (`FileVersion` = `0, 1, 0, 0`).

## 3. The smoke harness (`kindle_converter/ui/smoke.py`)

Three headless subcommands ship inside the artifact:

```text
KindleBookConverter.exe --smoke-check
KindleBookConverter.exe --smoke <input.pdf> <output-dir> [--azw3] [--expect-failure] [--report P]
KindleBookConverter.exe --sysinfo [--report P]
```

`--sysinfo` reports the frozen identity, runtime layout, dependency versions,
and external-tool availability (Tesseract/Calibre). `--smoke` drives the real
`MainWindow` workflow (select input -> analyze -> select output -> background
conversion) and structurally validates the produced EPUB. A conversion that
fails *because Tesseract is absent* (the M6.1 OCR-external behavior) is
reported `expected: true` with exit 0; the `--expect-failure` flag forces
expected reporting for any error during one-off manual checks. `ui/app.main`
dispatches the three commands off the real argument list before any window or
event loop is created.

## 5. Bugs found and fixed during verification

* **Frozen relative import** -- the initial spec entry was `ui/__main__.py`;
  the frozen exe crashed with `ImportError: attempted relative import with no
  known parent package`. Fixed with the absolute-import `windows_entry.py`.
* **Verifier launched the bundle directory, not the exe** -- `run_app`
  received the copied *folder*; `CreateProcess` on a directory raises
  `ERROR_ACCESS_DENIED` (Win32 5). Fixed to pass
  `scratch/KindleBookConverter.exe`. (The equal path length of the two
  strings masked the bug during manual probes.)
* **`pyi-grab_version` writes to a file, not stdout** -- the version check
  parsed empty stdout. Fixed to run it in a scratch directory and read the
  produced `file_version_info.txt`.
* **Pure-python packages live in the PYZ** -- `kindle_converter`,
  `ebooklib`, and `pytesseract` are not loose directories in an onedir
  bundle, and `python3*.dll` sits under `_internal`. The runtime-component
  checks now validate the real layout (12 components).
* **Frozen dependency versions were `unknown`** -- only the project's own
  metadata was copied into the bundle; the spec now copies all seven
  distributions' metadata, so the frozen `--sysinfo` resolves real versions.
* **False-positive dev-path check** -- the isolated sysinfo `sys_path` was
  flagged for the scratch-relative frozen runtime; the predicate now excludes
  the scratch root (legitimate) and keeps flagging real dev prefixes.

## 8. Known limitations

* A GUI/windowed exe detaches stdout and has no stdin; all machine-readable
  output goes through `--report`.
* The "clean machine" is an isolated bundle copy inside the repo's
  `build/` area, not a separate physical machine; it still runs the real
  frozen executable against the real M6.1 fixtures.
* Executing a freshly copied bundle can transiently fail with
  `ERROR_ACCESS_DENIED` while antivirus scans it; `run_app` retries process
  creation before reporting failure.
* The tooling directory is `build_tools` (not `packaging`) to avoid
  shadowing the third-party `packaging` distribution on `sys.path`.

## 9. M1–M5 impact

No production conversion behavior or public conversion API changed. Runtime
identity was added (`kindle_converter/_meta.py`, `__version__`), the window
entry gained a verification dispatch seam, and the new smoke module is never
imported on the normal GUI path.
