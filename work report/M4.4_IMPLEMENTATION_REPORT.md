# M4.4 — Cover Handling Implementation Report

## 1. Summary

Implemented **M4.4 — Cover Handling**: an explicit, optional cover that flows
`PDF → Book → EPUB` (and onward to AZW3) using the EPUB cover semantics
readers recognize. The cover is a filesystem path or an in-memory `Image`,
resolved and validated at the input boundary before any PDF work runs, then
rendered by the EPUB builder as:

- the packaged cover image with `properties="cover-image"` in the OPF manifest,
- a `name="cover"` package metadata entry pointing at that image,
- a minimal, reflowable XHTML cover page (`EPUB/cover.xhtml`) that reuses the
  project stylesheet and sits first in the spine, and
- **no** navigation entry: the cover never becomes a chapter, TOC entry, or
  NCX `navPoint`.

Cover handling is deliberately conservative: covers are never auto-detected
(no PDF filename heuristics, no first-page analysis), no image processing is
added, no format conversion happens, and a `Book` without a cover renders the
same EPUB structure as before.

## 4. Architecture

```text
PDF ─┐
     │  convert_pdf_to_book(cover=...)      convert_pdf_to_epub(cover=...)
     └─► load_cover(source) ─► Book.cover                 │
              │ validated before the PDF is opened        ▼
              ▼                                build_epub(Book, output)
         Book ──► EPUB (cover-image + name="cover" + cover.xhtml)
```

- `load_cover` accepts a filesystem path or an existing
  `kindle_converter.document.Image`. A path is read and its format is sniffed
  from the magic bytes (JPEG / PNG / GIF / SVG — the same supported set the
  EPUB builder already renders); an `Image` with a supported declared
  `content_type` is returned unchanged (never mutated, never copied), while
  one without a media type gets the sniffed type added on a fresh object.
  Nothing is ever inferred from the file name.
- The EPUB builder uses EbookLib's dedicated cover types rather than patching
  the generated ZIP/XML: an `EpubCover` item produces
  `properties="cover-image"` in the OPF manifest, the package metadata is set
  through `add_metadata(None, "meta", "", {"name": "cover", "content": "cover-img"})`,
  and the cover page is a normal `EpubHtml` linking the shared stylesheet.
- The cover never enters `book.toc`, so EbookLib excludes it from both
  `nav.xhtml` and `toc.ncx`; the spine (`nav`, `cover`, chapters) is the only
  place that references it.
- The AZW3 layer is untouched: it consumes the finished EPUB artifact, so a
  covered EPUB converts to AZW3 without any M4.4-specific changes.

## 5. Public API

```python
from kindle_converter.document import (
    load_cover,
    CoverError,
    CoverNotFoundError,
    CoverUnreadableError,
    CoverUnsupportedFormatError,
    CoverInvalidDataError,
)
from kindle_converter import convert_pdf_to_epub, convert_pdf_to_book
from kindle_converter.document import Image

convert_pdf_to_epub("book.pdf", "book.epub", cover="cover.jpg")
book = convert_pdf_to_book("book.pdf", engine, cover=Image(data=png, content_type="image/png"))
```

`cover` is keyword-only everywhere, `None` by default (no cover, unchanged
behavior), and accepts `str` / `pathlib.Path` / `os.PathLike` / an `Image`.

## 6. Error handling

| Error | Meaning |
| --- | --- |
| `CoverNotFoundError` | The cover source path does not exist. |
| `CoverUnreadableError` | The cover path is a directory or cannot be read. |
| `CoverUnsupportedFormatError` | The cover data is not JPEG/PNG/GIF/SVG. |
| `CoverInvalidDataError` | The cover data is empty. |

All are subclasses of `CoverError`. These errors surface from `load_cover`
and are raised **before** the PDF is opened by the pipeline, so an invalid
cover never wastes extraction work and never leaves a partial EPUB on disk.
At the EPUB layer, an image that cannot be identified keeps raising the
existing `InvalidImageError`.

`ebook-convert` on `PATH`).

## 9. Determinism

Covered EPUBs are as deterministic as coverless ones: the cover image
resource is always `images/cover.<ext>` (extension from the resolved media
type), the cover page is always `cover.xhtml` with id `cover`, the image id is
always `cover-img`, and the spine is always `["nav", "cover", *chapters]`.
The repeated-build test compares every `.xhtml`/`.css`/`.opf`/image byte of
two builds and asserts they are identical (the only accepted variation is
EbookLib's own `dcterms:modified` timestamp, as already documented for M4.1).
The no-cover path is unchanged: no cover resources, no cover metadata, spine
`["nav", *chapters]`.

## 10. Compatibility

- `Book.cover: Image | None = None` (pre-existing) is now consumed by the
  EPUB builder; `Book` construction is fully backward compatible.
- Existing EPUB generation is unchanged for coverless books — the regression
  tests in `tests/test_cover_handling.py` assert exactly that.
- EPUB validation (M4.2) validates covered EPUBs unchanged; the validator
  needed no changes.
- PDF/OCR/reconstruction layers (M1–M3) and the AZW3/Calibre layer (M4.3)
  are untouched.
- No new Python dependency: cover format sniffing reuses the byte-based magic
  table already used by the image pipeline.
