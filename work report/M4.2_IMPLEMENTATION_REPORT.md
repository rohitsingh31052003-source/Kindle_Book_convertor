# M4.2 — EPUB Validation Implementation Report

## 1. Summary

Implemented a dedicated, read-only EPUB validation layer for Milestone 4.2. The validator inspects a finished EPUB artifact independently of PDF processing and reports structured validation results. It detects malformed or structurally incomplete EPUB output before later stages such as AZW3 conversion.

The architecture now follows:

```text
PDF
 ↓
Book
 ↓
build_epub()
 ↓
EPUB
 ↓
validate_epub(EPUB)
 ↓
valid EPUB
```

## 4. Public API

```python
from kindle_converter.epub import (
    validate_epub,
    EPUBValidationResult,
    EPUBValidationIssue,
    EPUBValidationCode,
    EPUBValidationSeverity,
    EPUBValidationError,
)
```

### `validate_epub(source)`

- Accepts an EPUB artifact: a filesystem path or archive bytes.
- Does **not** accept a PDF or `Book`.
- Does **not** import PDF/OCR code.
- Returns an `EPUBValidationResult`.
- Raises `EPUBValidationError` only when the source is not an artifact or cannot be read at all.

### `EPUBValidationResult`

- `valid` — `True` when there are no errors.
- `errors` — immutable tuple of error findings.
- `warnings` — immutable tuple of non-fatal observations.
- `error_count`, `warning_count`, `format_report()`.
- `package_document`, `epub_version`, `spine_documents` carry structural facts when available.

### `EPUBValidationIssue`

- `code` — `EPUBValidationCode`.
- `message` — actionable diagnostic.
- `severity` — `ERROR` or `WARNING`.
- `location` — archive path or empty string.

### `EPUBValidationCode`

Machine-readable codes include:

- `INVALID_ARCHIVE`
- `DUPLICATE_ARCHIVE_ENTRY`
- `INVALID_ARCHIVE_ENTRY`
- `MISSING_MIMETYPE`
- `INVALID_MIMETYPE`
- `COMPRESSED_MIMETYPE`
- `MIMETYPE_NOT_FIRST`
- `MISSING_CONTAINER`
- `INVALID_CONTAINER`
- `MISSING_PACKAGE_DOCUMENT`
- `INVALID_PACKAGE_DOCUMENT`
- `UNSUPPORTED_EPUB_VERSION`
- `MISSING_METADATA`
- `MISSING_MANIFEST`
- `INVALID_MANIFEST`
- `MISSING_SPINE`
- `INVALID_SPINE`

- `INVALID_STYLESHEET`

- `UNDEFINED_PAGE_BREAK_STYLE`

## 5. Validation layers

- **ZIP/container** — invalid/unreadable ZIP handling, duplicate/invalid entry names, `mimetype` existence/content/stored-first check, `META-INF/container.xml` parseability, rootfile validity, and package document location.
- **OPF/package document** — namespace/version validation, required `metadata`, `manifest`, and `spine` presence.
- **Metadata** — non-empty title, language, identifier, and required `unique-identifier` matching a metadata identifier.
- **Manifest** — id/href/media-type validation, duplicate IDs/hrefs, packaged relative references, missing resources, media-type/image coherence, and required profile resources.
- **Spine** — itemref validation, dangling references, duplicate idrefs, navigation-in-spine check, NCX `toc` consistency, and deterministic spine document order.
- **XHTML** — XML well-formedness, required `html`/`head`/`body`, and structural page-break markers.
- **Internal references** — `img`, stylesheet links, anchors, and CSS `url()`/`@import` references resolve to packaged manifest resources.
- **CSS** — UTF-8 decodability, non-empty check, and packaged resource reference resolution.
- **Navigation** — EPUB 3 `nav` document structure, TOC links to packaged XHTML spine documents, and NCX structural checks when packaged.
- **Images** — manifest media-type/file-extension coherence and packaged image references.
- **Page breaks** — `page-break` class usage on empty `div` and stylesheet rule presence.

## 6. Pipeline integration

Validation is standalone. `convert_pdf_to_epub()` and the pipeline APIs are unchanged. This preserves backward compatibility and keeps validation an explicit output-quality check.

## 11. Known limitations

- Validation targets the structural EPUB profile produced by this project; it does not prove Kindle device rendering or marketplace acceptance.
- CSS validation is lightweight and does not implement a full CSS parser or Kindle compatibility proof.
- Image validation checks structural media-type/reference consistency and does not decode images.
- Navigation coherence is checked structurally, not for semantic PDF reading-order quality.
- The validator is deterministic for the same artifact but does not compare two different artifacts.
