# M3.6 Implementation Report - Improve Structural Reconstruction

## 1. Summary

Implemented M3.6: **OCR-aware structural reconstruction** that connects the
M3.5 per-page routing results (`PageProcessingResult`) into the existing M2
structural pipeline (reading order → paragraphs → headings → header/footer →
integrated document → chapters) so OCR-derived text becomes body paragraphs
in the same immutable `ReconstructedDocument` the M2 pipeline produces. Native
text processing stays byte-identical to Milestone 2.

```text
PDF
 │
 ▼
 page analysis / classification          (M3.1, reused unchanged)
 │
 ▼
 process_pages -> PageProcessingResult    (M3.5, reused unchanged)
 │
 ▼
 reconstruct_processed_pages        (M3.6, this milestone)
 │  ├─ native paragraphs  (M2.3 via M2.2/M2.1, byte-identical)
 │  └─ OCR paragraphs     (new: blank-line grouping, TextSource.OCR)
 ▼
 ReconstructedDocument (native first, OCR last per page; M2.9 chapters)
 │
 ▼
 reconstructed_document_to_book -> Book   (reused)
```

Key additions:

- **`TextSource`** (`StrEnum`: `NATIVE` / `OCR`) and a `source` field on
  `ReconstructedParagraph` (`paragraphs.py:185`, `paragraphs.py:237`) -- every
  paragraph now carries the provenance of its text. Default `NATIVE` keeps all
  existing positional construction backward compatible.
- **`reconstruct_ocr_paragraphs(text, page_number)`**
  (`paragraphs.py:658`) -- text-only paragraph reconstruction: blank lines are
  paragraph boundaries (runs of blanks collapse to one), consecutive non-blank
  lines are joined with the **same** conservative single-space/dehyphenation
  rule as native M2.3 paragraphs (shared `_join_texts`, `paragraphs.py:371`).
- **`reconstruct_processed_pages(results, *, layout=None, images=None)`**
  (`structural.py:93`) -- runs the full M2 stack over the deduplicated native
  `layout` unchanged, then appends each page's OCR paragraphs **after** its
  native paragraphs. For text-only documents the result is byte-identical to
  `reconstruct_layout(layout)`.
- **`processed_pages_to_book(results, metadata, *, layout=None, images=None)`**
  (`structural.py:194`) -- thin adapter to the document model via the reused
  `reconstructed_document_to_book`.
- **`convert_pdf_to_book(source, engine, *, renderer=None, dpi=...) -> Book`**
  (`pipeline.py:124`) -- the OCR-aware Book-level pipeline entry that accepts
  TEXT, SCANNED, and MIXED PDFs (the EPUB entry
  `convert_pdf_to_epub` still refuses SCANNED/MIXED, since EPUB output for OCR
  is M4 scope).
- **21 deterministic tests** (`tests/test_structural_reconstruction.py`) using
  synthetic PDFs and a fake OCR engine only (no Tesseract).

Per-page composition is deterministic and never merges sources:

- **TEXT** → native only (OCR is never run for these pages).
- **SCANNED** → OCR only (native text is `None`).
- **MIXED** → native paragraphs first, then the page's OCR paragraphs,
  distinct (`TextSource.NATIVE` vs `TextSource.OCR`), never concatenated and
  never de-duplicated. The M3.5 overlap policy is preserved.

## 4. Architecture

### Module location

`src/kindle_converter/pdf/structural.py`, following the package convention of
one focused submodule per concern. It is an **adapter / integration layer**,
not another detection algorithm: it combines existing detections and adds the
only new concept required -- reconstructing paragraphs from OCR text that has
no layout geometry.

### Reuse without modification

| Concern | Reused API (unchanged) |
|---|---|
| Classification | `PDFAnalysis`, `PageAnalysis`, `PDFType` (M3.1) |
| Routing | `process_pages`, `PageProcessingResult`, `PageRenderer` (M3.5) |
| Native structural stack | `reconstruct_layout`, `build_reconstructed_document`, `reconstructed_document_to_book`, `ordered_body_elements`, `deduplicate_layout` (M2.7) |
| Paragraph reconstruction | `reconstruct_paragraphs`, `ReconstructedParagraph`, `_join_texts` (M2.3) |
| Heading / furniture | `classify_paragraphs` (M2.4), `detect_headers_footers` (M2.5) |
| Chapters | `detect_chapters` (M2.9) |
| Images | `ImageExtractionResult`, attached per page as in M2.13 paths |

### How the adapter composes

`reconstruct_processed_pages`:

1. validates `results` (contiguous `1..N` sequence of `PageProcessingResult`,
   page identity preserved) and the optional `layout`;
2. when `layout` is provided, runs `reconstruct_layout(layout, images=images)`
   -- this is the historical M2 pipeline, unchanged -- to obtain the native
   paragraphs, headings, and furniture;
3. builds a combined `ParagraphLayout`: per page, the **native** paragraphs
   (by reference) followed by the page's **OCR** paragraphs
   (`_combine_paragraph_pages`, `structural.py:235`);
4. reuses `build_reconstructed_document` on the combined layout with the
   native-only headings and furniture (OCR paragraphs are never heading /
   furniture candidates because those detections consume geometry and run
   only over native paragraphs);
5. re-runs M2.9 `detect_chapters` on the integrated document and attaches it,
   exactly like `reconstruct_layout`.

### Ownership / resource handling

`convert_pdf_to_book` opens `source` once, shares the same open `Document`
across analysis, native layout extraction, and rendering/OCR, and closes it
when it opened it (caller-owned `Document` values are never closed), matching
the package convention and the M3.5 `process_pages` ownership contract.

## 5. OCR Paragraph Reconstruction

`reconstruct_ocr_paragraphs` (`paragraphs.py:658`) is the single new
paragraph-detection step. Because OCR provides no reading order and no
geometry, the only deterministic boundary signal is the line structure the
M3.4 cleanup layer already preserves:

- a blank line, or a run of blank lines, between non-empty lines is a
  paragraph boundary;
- consecutive non-blank lines form one paragraph and are joined by the shared
  `_join_texts` rule: single space between lines, conservative
  dehyphenation at line breaks (same guards as M2.3:
  `_likely_wrapping_hyphen`), up-to-4-space leading indent strip on the first
  line, whitespace collapse;
- whitespace-only paragraphs are never emitted; a page with no non-empty
  lines contributes nothing;
- page numbers are carried unchanged into every paragraph.

This keeps OCR text structurally readable (no flattening to one run of words)
without inventing layout signals that OCR does not provide.

## 6. Per-Page Composition

Within a page the element order is deterministic: **native paragraphs first,
then OCR paragraphs**, so a MIXED page reads native body followed by the
additional content OCR recognized. The two sources are kept as distinct
paragraphs tagged `TextSource.NATIVE` / `TextSource.OCR` and are never
concatenated, interleaved at word level, or de-duplicated -- even when the
full-page OCR re-recognizes the page's native text (the M3.5 overlap policy).
This module performs no fuzzy de-duplication (a later milestone).

## 7. Ordering & Page Boundaries

- Page identity is 1-based and preserved; page order is never changed.
- `ReconstructedDocument.pages` mirrors the source page sequence; empty pages
  survive as pages (page boundaries are structural).
- `reconstructed_document_to_book` maps each page boundary to one `PageBreak`
  and orders per page via `ordered_body_elements`.
- Because OCR paragraphs have no source geometry, `_element_top`
  (`reconstruction.py:325`) now sorts geometry-less elements **after** every
  geometry-bearing element on the same page (`+inf`) instead of to the top
  (`-inf`). This is the integration decision that keeps OCR content following
  native content. Native elements always carry geometry, so none of the M2
  behavior changes.

## 8. Provenance & Geometry Policy

- Every `ReconstructedParagraph` carries `source` (`TextSource.NATIVE` or
  `TextSource.OCR`), page number, and (for native) source lines/blocks, M2.1
  extraction order indices, and M2.2 reading-order indices.
- OCR paragraphs carry `TextSource.OCR` and **empty** `source_lines`,
  `source_blocks`, `source_line_orders`, and `reading_order_indices`. **No
  bbox, font, block, or reading-order metadata is fabricated for OCR text.**
- OCR paragraphs are never heading or header/footer candidates: M2.4/M2.5
  classification runs only over the native paragraph layout, and M2.9 chapter
  detection only ever promotes native headings.
- When `layout` is omitted, `reconstruct_processed_pages` runs in OCR-only
  mode (`layout=None`): native contribution is skipped and geometry-free page
  shells (`structural.py:283`, width/height `0.0` marks "unknown") keep page
  count and order honest. The pipeline always passes the layout.

## 9. Error Handling & Validation

`reconstruct_processed_pages` fails eagerly and deterministically:

- `TypeError` -- `results` is not a sequence, an element is not a
  `PageProcessingResult`, or `layout` is not a `PageLayout`.
- `ValueError` -- `results` is empty, page numbers are not the contiguous
  `1..N` sequence in order (gap, duplicate, or out-of-order), or `layout`'s
  page count does not match `len(results)`.

`reconstruct_ocr_paragraphs`:

- `TypeError` -- `text` is not a `str`.
- `ValueError` -- `page_number` is not a positive integer.

`convert_pdf_to_book` propagates the existing M3.5/M3.3/M3.2 errors unchanged
(`PDFReadError`, `EmptyPDFError`, `PDFRenderingError`, `OCRError` incl.
`OCREngineUnavailableError` with page context) and never catches or silences
OCR failures.

## 11. Tests

`tests/test_structural_reconstruction.py` (21 tests), deterministic, no
Tesseract:

- **`TestNativeRegression`** (2) -- a TEXT-only document reconstructed via
  `reconstruct_processed_pages(results, layout)` is byte-identical to
  `reconstruct_layout(layout)` (element snapshot, paragraph layout, chapter
  detection); TEXT pages keep `TextSource.NATIVE`.
- **`TestOCRParsing`** (5) -- an OCR-only page builds body paragraphs with
  empty provenance and `TextSource.OCR`; blank-line runs collapse to one
  boundary; consecutive non-blank lines join with dehyphenation; OCR text that
  looks like a heading ("Chapter 1") is nevertheless a paragraph and never a
  chapter; empty OCR text contributes nothing.
- **`TestMixedPages`** (3) -- native paragraphs come before OCR paragraphs on a
  MIXED page; identical native/OCR content is kept as distinct sources (no
  merge, no de-dup); page breaks and source order survive into the
  document-model `Book`.
- **`TestValidation`** (6) -- empty results, page gaps, out-of-order pages,
  non-`PageProcessingResult` values, wrong `layout` type, and layout page-count
  mismatch are all rejected.
- **`TestDeterminism`** (1) -- repeated runs produce an identical document
  (value and structural equality).
- **`TestPipeline`** (4) -- `convert_pdf_to_book` on a text PDF matches
  `extract_book` body text; a scanned PDF yields OCR body paragraphs (exactly
  one call per scanned page); a MIXED document keeps native text before OCR
  text; an invalid engine is rejected eagerly.

## 15. Known Limitations / Deferred Work

M3.6 integrates OCR text into structural reconstruction but explicitly does
**not** implement:

- EPUB output from OCR-composed books (SCANNED/MIXED documents remain
  unavailable to `convert_pdf_to_epub`; that is M4 scope);
- geometric alignment between native spans and OCR output (image-only region
  detection);
- de-duplication of the intentional native/OCR overlap on MIXED pages (no
  fuzzy de-dup by policy);
- caption/table/figure identification;
- OCR heading detection (OCR contributes body paragraphs only);
- reading-order reconstruction for OCR (blank-line grouping is the only
  deterministic signal OCR preserves);
- placeholder page shells when `layout` is omitted use width/height `0.0`
  purely as an "unknown geometry" marker (never used as text geometry).
