# M3.3 Implementation Report - OCR Processing

## 1. Summary

Implemented M3.3: the project's first **OCR processing layer**, establishing a
clean boundary between PDF rendering, OCR execution, and OCR result
representation:

```text
PDF
 │
 ├── native text analysis/extraction        (unchanged M3.1 / M2)
 │
 └── PDF page renderer  (M3.2)
          │
          ▼
     RenderedPage
          │
          ▼
      OCR engine       (ocr.py, M3.3)
          │
          ▼
     OCRResult
```

The OCR layer consumes exactly the **M3.2 `RenderedPage`** output; it never
reopens the PDF and never calls PyMuPDF rendering itself. OCR is kept behind a
small, explicit `OCREngine` abstraction so a future engine can replace the
implementation without touching the PDF pipeline. M3.3 ends at
`image -> recognized text`; it performs **no** OCR cleanup, **no** structural
reconstruction, and **no** automatic scanned-page routing.

Key additions:

- **`ocr_page()` / `ocr_pages()`** - application-level API consuming
  `RenderedPage` and returning typed `OCRResult` values (single page and a
  lazy, sequential, order-preserving multi-page iterator).
- **`OCREngine`** - a `typing.Protocol` abstraction (`recognize(image) -> str`)
  so engines are injected; no hidden global engine is ever created.
- **`OCRResult`** - frozen/slots value object preserving the 1-based page
  number and the raw recognized text (no cleanup).
- **`TesseractEngine`** - the built-in local OCR engine wrapping the external
  **Tesseract executable** via the small `pytesseract` wrapper. The Python
  wrappers are an optional `ocr` extra; the Tesseract binary is an external
  runtime requirement that is never downloaded or installed by the project.
- **`OCRError` / `OCREngineUnavailableError`** - focused OCR exceptions; the
  affected (1-based) page number is preserved in every runtime-failure message.
- 62 deterministic unit tests (fake engine, no external OCR) and 8 optional
  integration tests (real Tesseract; auto-skip when unavailable).

## 4. OCR Architecture

### Module location

`src/kindle_converter/pdf/ocr.py`, following the package convention of one
focused submodule per milestone (`renderer.py`, `analyzer.py`, ...).

### Data flow

```text
renderer.render_page(...)/render_pages(...)
                    │
                    ▼
               RenderedPage            (M3.2: page_number, dpi, RGB pixmap)
                    │
                    ▼
ocr.ocr_page(rendered_page, engine)     (validates, preserves page_number)
ocr.ocr_pages(rendered_pages, engine)   (sequential generator over pages)
                    │
                    ▼
       OCREngine.recognize(image) -> str    (injected; e.g. TesseractEngine)
                    │
                    ▼
         OCRResult(page_number, text)       (raw text, no cleanup)
```

### Engine abstraction and dependency injection

`OCREngine` is a `typing.Protocol`:

```python
class OCREngine(Protocol):
    def recognize(self, image: pymupdf.Pixmap) -> str: ...
```

Engines are **required arguments** to `ocr_page`/`ocr_pages`; there is no
default-engine creation and no hidden global OCR state. Callers (and tests)
supply a fake or real engine explicitly. This makes the application-level
layer fully deterministic and independent of any external OCR executable.

### Relationship to the M3.2 renderer

`render_page`/`render_pages` (M3.2) are the sole PDF-to-raster path. The OCR
module imports `RenderedPage` from `.renderer` and consumes
`RenderedPage.image` (the pixmap) as-is: no `get_pixmap()` call, no reopening
of the PDF, no duplicated DPI/rendering logic. The renderer file itself was
**not** modified.

### Result representation

`OCRResult` is a frozen, slots-based dataclass carrying only the 1-based page
number and the raw recognized text. Confidence/engine metadata were
deliberately **not** forced into the model: for M3.3 the important output is
the recognized text. No paragraph/heading/line/layout fields exist (those
belong to later milestones).

## 5. OCR Engine

### Selected engine

**Tesseract**, invoked through the **pytesseract** Python wrapper, chosen as
the simplest appropriate local/offline OCR engine for this repository.

### Python dependency (optional `ocr` extra)

- `pytesseract>=0.3.13,<1` - thin wrapper around the Tesseract executable.
- `Pillow>=10.0,<13` - required by pytesseract to decode the pixmap PNG.

Both are declared as the optional `ocr` extra in `pyproject.toml`, so users
who only convert native-text PDFs never install OCR infrastructure. The OCR
public API (`OCRResult`, `ocr_page`, ...) remains importable without the
extra; only `TesseractEngine` requires it. `ocr.py` imports pytesseract/Pillow
**lazily** inside `TesseractEngine.__init__`, keeping the whole package
import-safe without the extra.

### External runtime dependency

The **Tesseract executable** is a separate runtime requirement. This project
never downloads, installs, or re-distributes it; installing pytesseract/Pillow
provides only the Python wrapper, not the binary. Failure to find the binary
raises `OCREngineUnavailableError` with actionable guidance.

### Executable discovery

- **Normal PATH discovery**: when no `tesseract_cmd` is passed, pytesseract's
  default `tesseract` command is used (resolved via `PATH`).
- **Explicit configuration**: `TesseractEngine(tesseract_cmd="C:/.../tesseract.exe")`
  accepts any `str`/`os.PathLike`. An explicit path that does not exist fails
  eagerly at construction with `OCREngineUnavailableError`.
- **Documentation**: the optional integration tests and the README additionally
  honor the `TESSERACT_CMD` environment variable (test-time only).
- No machine-specific default path is hard-coded anywhere in the implementation.

### Configuration

Intentionally small: only `language` (default `DEFAULT_OCR_LANGUAGE = "eng"`,
no automatic language detection) and `tesseract_cmd`. Page segmentation uses a
fixed internal default (`--psm 3`, fully automatic segmentation without OSD),
chosen as a general-purpose mode for book pages; it is not part of the public
configuration surface.

### Failure behavior

| Situation | Result |
|---|---|
| `pytesseract`/`Pillow` not installed | `OCREngineUnavailableError` (tells the user to `pip install -e ".[ocr]"`) |
| Explicit `tesseract_cmd` does not exist | `OCREngineUnavailableError` at construction |
| Tesseract not found on PATH | `OCREngineUnavailableError` before running |
| Tesseract runs but errors (e.g. unknown language) | `OCRError` (chained from `pytesseract.TesseractError`) |
| Image cannot be serialized/decoded | `OCRError` |
| Caller argument problems (bad page, image, language, cmd) | `TypeError` / `ValueError` (no domain exception added) |

All runtime failures escaping `ocr_page`/`ocr_pages` carry the affected
**1-based page number** in the message. Exceptions are preserved with their
original types via chaining; unknown exceptions propagate unchanged (no broad
swallowing).

### Lifecycle

`TesseractEngine` is a cheap, effectively stateless configuration object
(language + executable path) safe to construct once and reuse across pages
(verified by an integration test). No caching, no worker pool, no
parallelization. Pages are processed strictly sequentially.

One pytesseract API limitation is handled inside the engine: pytesseract
exposes the executable path only as a module global, so the engine pins that
global to a deterministic target (the explicit `tesseract_cmd`, or the
`"tesseract"` default) on every invocation. This is the OCR layer's only
global touch and is confined to `TesseractEngine`; the application-level API
behaves purely through dependency injection.

by a test).

## 7. OCR Behavior

- **Input representation**: `RenderedPage` (M3.2) - 1-based `page_number`,
  `dpi`, and the RGB `pymupdf.Pixmap` (`image`).
- **Output representation**: `OCRResult(page_number, text)` where `text` is the
  raw text returned by the engine, preserved **verbatim** including line breaks
  and trailing whitespace (no application-level cleanup).
- **Page numbering**: 1-based physical PDF page indices, carried unchanged from
  `RenderedPage` through to `OCRResult`.
- **Multi-page processing**: `ocr_pages` is a lazy generator that processes
  pages one at a time in input order (bounded memory), matching
  `render_pages`' architecture. Failures are never skipped: the first failure
  propagates with its page number and stops iteration.
- **Language/configuration**: explicit `language` (default `"eng"`); automatic
  language detection is not implemented.
- **Error semantics**: `TypeError`/`ValueError` for invalid callers'
  arguments; `OCRError`/`OCREngineUnavailableError` for engine/runtime
  failures; page context present in all runtime failures.

## 8. Tests

### Deterministic fake-engine tests (`tests/test_pdf_ocr.py`, 62 tests)

Run in every normal suite; no pytesseract, Pillow, or Tesseract needed.

- **`OCRResult` representation**: fields, frozen/slots, equality.
- **Input/output contract**: `ocr_page` returns `OCRResult`, engine receives
  the exact rendered image, page number preserved, engine text returned
  verbatim (no cleanup), duck-typed `OCREngine` accepted.
- **Engine injection**: engines injected per call, single engine reused across
  pages, no hidden default engine, missing/non-callable engines rejected.
- **Multi-page**: order + page numbers, sequential processing, generator
  input, lazy generation (nothing OCR'd before iteration).
- **Renderer/OCR boundary**: a real M3.2 `render_page`/`render_pages` output
  flows into the OCR API; an already-open document stays owned/closed-untouched
  (OCR never reopens or closes the PDF).
- **Validation**: non-`RenderedPage` inputs, `None`/non-pixmap/zero-dimension
  images, non-str engine results, non-iterable `ocr_pages` inputs, invalid
  elements.
- **Error propagation**: `OCRError` gets page context, unavailability subtype
  preserved, unknown exceptions propagate unchanged, multi-page failures carry
  the failing page number and stop processing (not skipped).
- **`TesseractEngine` argument validation**: invalid language (`None`, `""`,
  whitespace, `True`, `int`, `bytes`, `list`) and invalid `tesseract_cmd`
  raise `ValueError` **before** any optional dependency import (works even
  without the `ocr` extra).
- **Public API**: exports present, internal helpers absent from `__all__`,
  exception hierarchy, OCR submodule importable without the extra.

### Optional real-engine integration tests (`tests/test_pdf_ocr_tesseract.py`, 8 tests)

Enabled by `TESSERACT_CMD` (environment variable) or a PATH-discoverable
`tesseract`; the module skips cleanly when `pytesseract` is missing or no
executable is found. Never downloads an engine; all inputs are tiny synthetic
PyMuPDF-generated PDFs (no network).

- Engine unavailability (deterministic, no binary needed): missing explicit
  executable -> `OCREngineUnavailableError` with actionable message;
  existing-but-unrunnable executable -> `OCRError` on recognize, plus a check
  that the pytesseract global is pinned deterministically.
- Real recognition: a synthetic 300-DPI page containing known words (e.g.
  "quick brown fox"); one engine reused across pages; raw-text preservation;
  unknown language -> `OCRError`.
- PATH discovery: real recognition via `TesseractEngine()` when `tesseract`
  is on PATH (skipped otherwise).

## 12. Runtime Requirements

OCR support requires, in addition to the Python `ocr` extra:

- **External Tesseract executable** (Tesseract 5.x recommended, any recent
  build with the `eng` traineddata). It is installed by Tesseract's own
  installer - never by this project - and is discovered on `PATH` or via an
  explicit `TesseractEngine(tesseract_cmd=...)` path. The optional integration
  tests also honor `TESSERACT_CMD`.
- Verify with `tesseract --version` and `tesseract --list-langs` (must list
  `eng`). When unavailable, only the optional OCR integration tests skip; the
  deterministic core suite never requires Tesseract (no binary is downloaded).

## 13. Known Limitations

M3.3 implements only the OCR **capability** (`image -> recognized text`). It
explicitly does **not** implement:

- **OCR cleanup** (whitespace/Unicode normalization, hyphenation repair,
  ligature normalization, repeated header/footer removal, typo correction,
  confidence filtering) - M3.4.
- **OCR correction** / language-model correction.
- **Mixed-document OCR routing** (deciding which pages to OCR) - M3.5.
- **Paragraph reconstruction**, **heading detection**, or any structural
  reconstruction from OCR text (paragraphs, headings, lists, tables,
  chapters, EPUB structure).
- **Automatic OCR fallback** - `extract_book` still refuses scanned/mixed
  PDFs.
- Automatic language detection; language must be passed explicitly.
- OCR preprocessing (deskewing, thresholding, denoising); the engine receives
  the raw rendered raster exactly as the M3.2 renderer produced it.
- Caching, parallelization, worker pools, persistence of OCR output.

The engine's output is returned verbatim; if Tesseract itself performs
low-level normalization internally, that is the engine's own behavior and is
not supplemented by application-level processing.
