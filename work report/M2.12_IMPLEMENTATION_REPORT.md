# M2.12 Implementation Report — Metadata Handling

## 1. Summary

M2.12 completes the README's Milestone 2 requirement **"Metadata handling"**.

The project already carried a shared metadata field on the format-independent
document model (`BookMetadata` in
`src/kindle_converter/document/models.py`). Rather than invent a competing
representation, M2.12 **extends that existing model minimally** and adds a
small, deterministic, conservative metadata *handling* layer around it:

* `BookMetadata` gains two missing fields — `description` and `subject` — so it
  now supports the seven V1 bibliographic fields (title, author, language,
  publisher, description, subject, identifier), with every field defaulting to
  the empty string.
* A new `src/kindle_converter/pdf/metadata.py` module provides two public
  operations:
  * `extract_pdf_metadata(source)` — reads only PyMuPDF's `Document.metadata`
    dictionary (never page text, OCR, or any external source) and maps it onto
    a `BookMetadata`.
  * `resolve_metadata(explicit, pdf)` — deterministically combines caller
    metadata with PDF metadata following an explicit-wins /
    PDF-fills-the-gap rule.
* The existing extractor's private `_build_metadata` now delegates to the new
  public `extract_pdf_metadata`, so there is a single, tested extraction path.
* The EPUB builder now emits `dc:description` and `dc:subject` when present,
  so the new fields actually reach the output without redesigning the
  generator.

The scope is deliberately conservative for V1: no image/OCR/cover work, no
web scraping, no AI/LLM inference, no network access, and no invented or
guessed metadata.

## 4. Metadata model / API

**Model** — the shared `BookMetadata` dataclass (`slots=True`) now supports:

```
title, author, language, publisher, identifier, description, subject   (all str, default "")
```

Unknown/absent fields are represented by the empty string, matching the
existing convention. `is_empty` reports whether every field is an empty string.

**API** — public functions exported from `kindle_converter.pdf`:

```python
extract_pdf_metadata(source: PathLike | pymupdf.Document) -> BookMetadata
resolve_metadata(explicit: BookMetadata, pdf: BookMetadata) -> BookMetadata
```

* `extract_pdf_metadata` accepts a path (opened and closed within the call) or
  an already-open `pymupdf.Document` (never mutated, never closed; caller keeps
  ownership — mirroring the analyzer/extractor contract). It raises the
  existing `PDFReadError` for an unreadable path.
* `resolve_metadata` raises `TypeError` when either argument is not a
  `BookMetadata` (consistent with other M2 public APIs).

## 5. Metadata source priority

For a given field, the effective value comes from the most reliable source that
is present, in order:

1. **Explicit caller-provided metadata** (`resolve_metadata`'s `explicit`
   argument) — authoritative and preserved exactly.
2. **Reliable PDF document metadata** (`Document.metadata`, via
   `extract_pdf_metadata`) — fills only fields the caller left empty.
3. Existing document/book metadata already on the model (`Book.metadata`) —
   the `Book` carries the resolved `BookMetadata`.
4. Conservative document-derived title — already handled by the chapter
   adapter (`reconstructed_document_to_book` titles the single chapter from the
   resolved title); no further inference is performed.

With no explicit and no PDF metadata, every field remains empty — no value is
guessed.

## 6. Metadata resolution rules

`resolve_metadata(explicit, pdf)` maps every field uniformly and
deterministically:

* **explicit wins** — a present explicit value overrides the PDF value
  completely and is preserved exactly;
* **PDF fills the gap** — a field the caller left missing falls back to the PDF
  value, if present;
* **otherwise empty** — a field with neither source is left `""`.

Because explicit values are never overwritten by PDF values, the rule from the
specification ("explicit wins; PDF fills missing fields") is satisfied exactly.

## 7. Validation / normalization rules

* **Presence** — a value is *present* if and only if it is a non-empty string
  after stripping. `None` (defensive), non-strings, `""`, and whitespace-only
  strings are all treated as **missing**.
* **No destructive normalization** — present values are preserved exactly as
  supplied: capitalization, punctuation, internal spacing, and author names are
  never stripped or rewritten. Only the *presence* decision strips; the stored
  value is returned unchanged.
* **Minimal validation** — no complex metadata validation is introduced in
  M2.12. The only hard checks are the `TypeError` guards already described.

The pre-existing `BookMetadata.is_empty` model property is left as-is (raw
non-empty-string truthiness); whitespace-only handling is the responsibility of
the handling layer, which is where the specification's "whitespace-only →
missing" rule lives.

## 8. Integration points

* **PDF → `Book`** (extractor):
  `extract_book` → `_build_book` → `_build_metadata(doc)`, which now
  delegates to the public `extract_pdf_metadata(doc)`. `Book.metadata` is the
  integration point; `reconstructed_document_to_book` titles the fallback
  single chapter from the resolved title. Behaviour for existing PDFs is
  unchanged.
* **EPUB output** (builder): `_add_metadata` already emitted
  `dc:title`/`dc:creator`/`dc:language`/`dc:publisher`/`dc:identifier`; M2.12
  adds `dc:description` and `dc:subject` emission when non-empty. Empty values
  emit nothing, so existing EPUB output is unchanged. No redesign of the
  generator was needed.
* **Public pipeline**: `convert_pdf_to_epub` works unchanged and carries PDF
  metadata through to the EPUB (covered by an integration test).

## 11. Backwards compatibility

* `BookMetadata.description`/`subject` are keyword fields defaulting to `""`;
  every existing construction (`BookMetadata()`, 4-field/5-field variants,
  `Book()`, `Book(metadata=..., chapters=...)`) behaves as before.
* `Book.metadata` / `Book.chapters` / `cover` / `add_chapter` / `add_block`
  are untouched; `Book()` remains valid with a fresh metadata object and an
  empty chapter list.
* The extractor's PDF→`BookMetadata` mapping is byte-for-byte the pre-M2.12
  convention, now exercised through one shared function.
* The EPUB builder emits strictly more metadata only when new non-empty
  fields exist; metadata-less books produce identical output to before.
* No existing test was modified, weakened, deleted, or skipped.

## 12. Known limitations

* `description` and `subject` can only be set explicitly by the caller in V1;
  no reliable PDF key is mapped to them.
* `keywords`, `creator` (beyond publisher), and `producer` are not surfaced;
  only the project's established subset is mapped.
* `language` comes from PDF `language` only when present; PyMuPDF often omits
  it, in which case EPUB generation falls back to its pre-existing
  `DEFAULT_LANGUAGE = "en"` package default.
* `BookMetadata.is_empty` uses raw truthiness (pre-existing); whitespace-only
  strings count as non-empty there — the handling layer treats them as
  missing instead.
* No ISBN parsing/validation: `identifier` is an opaque string, never
  inferred from page numbers or body text.
* No cover/OCR/image/external-lookup behaviour was added (M2.13 and M3
  territory).
