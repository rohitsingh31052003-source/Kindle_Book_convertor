## 2. Public API

### New Classes and Functions

**`HeaderFooterType`** (`StrEnum`):
- `HEADER`: Indicates header detection
- `FOOTER`: Indicates footer detection

**`DetectedHeaderFooter`** (dataclass, frozen, slots=True):
- `text`: Normalized text content
- `kind`: HeaderFooterType (HEADER or FOOTER)
- `pages`: Tuple of page numbers where text appears
- `confidence`: Float confidence score (0.0 to 1.0)
- `reasons`: Tuple of reason strings explaining detection
- `source_paragraphs`: Tuple of source `ReconstructedParagraph` objects

**`HeaderFooterPage`** (dataclass, frozen, slots=True):
- `page_number`: Page number
- `detected`: Tuple of `DetectedHeaderFooter` objects on this page

**`HeaderFooterLayout`** (dataclass, frozen, slots=True):
- `pages`: Tuple of `HeaderFooterPage` objects
- `detected`: Tuple of all `DetectedHeaderFooter` objects

**`detect_headers_footers(source: ParagraphLayout) -> HeaderFooterLayout`**:
- Main detection function that analyzes paragraph layout and returns structured results

**`classify_header_footer_paragraphs(source: ParagraphLayout) -> Tuple[HeaderFooterLayout, list[ClassifiedHeaderFooterParagraph]]`**:
- Optional paragraph-level classification (currently returns empty list for paragraph classifications)

### Constants

- `MIN_REPEATED_PAGES = 3`: Minimum distinct pages required for classification
- `HEADER_REGION_FRACTION = 0.15`: Fraction of page height defining header region
- `FOOTER_REGION_FRACTION = 0.15`: Fraction of page height defining footer region
- `HEADER_POSITION_TOLERANCE_FRACTION = 0.03`: Positional tolerance for headers
- `FOOTER_POSITION_TOLERANCE_FRACTION = 0.03`: Positional tolerance for footers

## 3. Input/Output Contract

### Input
- **Source**: `ParagraphLayout` from M2.3 paragraph reconstruction
- Contains all pages in reading order with full provenance (source lines, blocks, page numbers)

### Output
- **Primary**: `HeaderFooterLayout` containing:
  - `pages`: List of `HeaderFooterPage` objects (one per page)
  - `detected`: List of all detected header/footer elements
- **Secondary**: `detected` elements contain full provenance to source paragraphs

## 4. Detection Algorithm

### Core Logic

1. **Collect all paragraphs** with their page numbers and geometry
2. **Normalize text** for comparison (whitespace collapse, trimming)
3. **Group by normalized text** to find candidates
4. **Filter candidates** by minimum page count (`MIN_REPEATED_PAGES = 3`)
5. **Classify by position**:
   - If primarily in header region → `HEADER`
   - If primarily in footer region → `FOOTER`
   - Otherwise → skip (not considered page furniture)
6. **Check positional consistency**:
   - Header: max deviation ≤ `HEADER_POSITION_TOLERANCE_FRACTION`
   - Footer: max deviation ≤ `FOOTER_POSITION_TOLERANCE_FRACTION`
7. **Calculate confidence**:
   - 50% weight: repetition count (3+ pages = 1.0, less = scaled)
   - 30% weight: positional consistency (0.0 to 1.0)
   - 20% weight: page coverage (fraction of total pages)

### Key Design Principles

- **Conservative**: Only detects clear, repeated patterns
- **Deterministic**: No randomness, sorted outputs
- **Provenance-preserving**: Maintains links to source paragraphs
- **Position-focused**: Relies on consistent positioning rather than content alone
- **Multi-signal**: Requires combination of repetition + positional consistency

## 5. Normalization Rules

- Text normalization: whitespace collapse and trimming
- No semantic normalization (case, spelling, etc.)
- No fuzzy matching - exact string matching after normalization

## 6. Repetition Logic

- Requires appearance on `MIN_REPEATED_PAGES = 3` distinct pages
- Does not count multiple occurrences on the same page
- Does not invent evidence for short documents (<3 pages)

## 7. Positional Logic

- Uses normalized page geometry (fraction of page height)
- Header region: top 15% of page height
- Footer region: bottom 15% of page height
- Positional tolerance: 3% of page height
- Vertical position is primary signal; horizontal position considered but not required

## 8. Page-Number Detection

- Supports common page number formats:
  - `1`, `2`, `3`, `4`
  - `- 1 -`, `Page 1`, `1 of 100`, etc.
- Requires bottom-page positioning and repetition
- Numeric sequences are treated as patterns, not individual numbers

## 9. Header vs Footer Classification

- **HEADER**: Text consistently near top of page (within header region)
- **FOOTER**: Text consistently near bottom of page (within footer region)
- Text at substantially different vertical positions → treated conservatively
- Same text at both top and bottom → treated as separate candidates

## 10. Avoiding False Positives

- **Repetition alone insufficient**: Body text that repeats is not classified
- **Position alone insufficient**: Unique text near edges is not classified
- **Positional inconsistency disqualifies**: Same text at varying positions → no confidence
- **Content type awareness**: Page numbers, copyright notices, etc. are recognized patterns

## 11. Edge Cases Handled

- **Empty pages**: No detection
- **Single-page documents**: No false repeated-page detection
- **Two-page documents**: No false repeated-page classification (requires 3+ pages)
- **Different page sizes**: Uses normalized geometry
- **Rotated pages**: Uses existing layout coordinates
- **Multiple candidates**: Allows multiple headers/footers per page
- **Same text top/bottom**: Treated as independent candidates
- **Near-threshold values**: Tested at/below/above critical values

## 12. Determinism

- **Sorted outputs**: By page number, then position, then text
- **No randomness**: All calculations deterministic
- **Fixed thresholds**: Constants are not tunable at runtime
- **Same input → same output**: Verified through comprehensive testing

## 15. Known Limitations

1. **Page number pattern recognition**: Currently basic string matching; may miss complex patterns
2. **No OCR support**: Relies on existing text extraction (M2.3)
3. **No language support**: Assumes English text patterns
4. **No semantic understanding**: Purely layout and repetition based
5. **Performance**: O(n²) in worst case due to grouping and sorting
