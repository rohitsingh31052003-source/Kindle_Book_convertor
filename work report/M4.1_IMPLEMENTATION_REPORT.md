# M4.1 Implementation Report - Kindle-ready EPUB Foundation

## 1. Summary

Implemented M4.1: **EPUB generation is now the production output path for
every supported PDF**, through one unified pipeline:

```text
PDF -> convert_pdf_to_book() -> Book -> build_epub() -> EPUB
```

TEXT, SCANNED, and MIXED PDFs all produce a format-independent `Book` first
(native reconstruction, OCR-aware reconstruction, or both kept separate), and
exactly one EPUB renderer consumes that `Book`. The M1.5-era restriction that
made `convert_pdf_to_epub` reject SCANNED/MIXED PDFs was removed; the EPUB
layer still contains no PDF/OCR logic, and the EPUB output was profiled as a
conservative, reflowable, Kindle-oriented ebook.

Files:

* `src/kindle_converter/pipeline.py` — unified composition
* `src/kindle_converter/epub/builder.py` — Kindle-oriented rendering profile
* `tests/test_kindle_epub.py` — 27 new deterministic tests
* `tests/test_pipeline.py` — scanned/mixed behavior updated
* documentation: `README.md`, package docstrings, `pdf/extractor.py` docstrings

## 2. Pipeline changes

* `convert_pdf_to_epub(source, output, *, engine=None, renderer=None, dpi=...)`
  (`pipeline.py:69`) is now plain composition:

  ```python
  book = convert_pdf_to_book(source, _resolve_engine(engine),
                             renderer=renderer, dpi=dpi)
  build_epub(book, output)
  ```

* `convert_pdf_to_book` (`pipeline.py:152`) now also runs the existing M2.13
  image extraction (`extract_pdf_images`) and passes the result into
  `reconstruct_processed_pages(..., images=images)`. This keeps TEXT output
  identical to the historical `extract_book` path (including images) and gives
  SCANNED/MIXED books their embedded images, with no new extraction pipeline.
* `_require_supported` (which raised `ScannedPDFError` / `MixedPDFError` from
  the EPUB pipeline) was deleted. Those exceptions remain public API of
  `extract_book`, which is still a text-only extractor.
* `_resolve_engine` / `_DeferredTesseractEngine` (`pipeline.py:271`) keep the
  optional OCR stack out of the import path: the built-in `TesseractEngine` is
  constructed only for the first page that actually needs recognition, so
  `TEXT -> EPUB` works in a base installation while SCANNED/MIXED documents
  run OCR (or fail with `OCREngineUnavailableError`) as appropriate.

Behavior by classification:

| PDF type | Route | Uploaded to EPUB |
| --- | --- | --- |
| TEXT | native layout + M2 reconstruction (byte-identical to `extract_book`) | yes |
| SCANNED | render -> OCR -> cleanup -> OCR paragraphs | yes |
| MIXED | native paragraphs first, then OCR paragraphs (never merged) | yes |

## 3. EPUB changes

* **One rendering path.** `build_epub(book, output, *, language=None)` is
  unchanged; the builder still consumes only `Book` (`Heading`, `Paragraph`,
  `Image`, `PageBreak`, `Chapter`, `BookMetadata`).
* **Kindle-oriented stylesheet** (`builder.py`, `STYLESHEET_CSS`): relative
  units only, body/paragraph/heading/image/page-break defaults, no fixed page
  dimensions, no absolute positioning, no viewport units, no JavaScript, no
  external resources, no grid/flex layout, no animations. Page margins are
  left to the reading system; the CSS only controls block flow.
* **Semantic structure** unchanged and verified: headings stay `<h1>`–`<h6>`,
  paragraphs `<p>`, images `<img class="image">`, `PageBreak` an empty
  `div.page-break`.
* **Page breaks** still use `page-break-after: always` plus the CSS3
  `break-after: always` counterpart and `height: 0`, so a PDF page boundary
  never becomes a fixed PDF-sized page.
* **Images** keep their original bytes and media types, are deduplicated per
  asset token, and are constrained with `max-width: 100%; height: auto`
  (no `width`/`height`/`style` attributes are emitted).
* **Chapters and navigation** unchanged: one `EpubHtml` per chapter
  (`chapter-NN.xhtml`), TOC + spine in document order, EPUB 3 `nav.xhtml`
  plus `toc.ncx`, chapter titles as document titles and navigation labels.
* **Metadata** unchanged: title, language (with `language=` override),
  author, publisher, identifier/UID, description, subject.
* **Determinism**: resource names, chapter order, spine, TOC, CSS, and image
  bytes are deterministic. The only non-logical variation is EbookLib's own
  container metadata (`dcterms:modified` and ZIP entry times), which is
  documented rather than worked around.

## 4. Tests

* **New:** `tests/test_kindle_epub.py` — 28 deterministic tests covering
  TEXT/SCANNED/MIXED `PDF -> Book -> EPUB`, structure and ordering,
  navigation/spine, image bytes/media types/order/reflowable markup,
  Kindle-oriented CSS (including forbidden fixed/web layout techniques and
  absence of JavaScript), determinism, and required container resources.
  All OCR uses an injected fake engine; the module never needs Tesseract.
* **Updated:** `tests/test_pipeline.py` — the two obsolete rejection tests
  (`test_scanned_pdf_raises`, `test_mixed_pdf_raises`) were replaced by
  `test_scanned_pdf_converts_through_ocr_book_pipeline` and
  `test_mixed_pdf_converts_through_unified_pipeline` (fake OCR engine). The
  module now also exposes a reusable `FakeOCREngine`.
* **Unchanged and still passing:** every M1–M3 test module, including
  `test_image_extraction.py::test_full_pipeline_with_image` and
  `test_pipeline.py::test_pipeline_matches_manual_stages` (the unified
  pipeline produces byte-identical EPUBs to `extract_book` + `build_epub`
  for TEXT PDFs).

Results: `1073 passed, 5 skipped` (baseline before M4.1: `1045 passed, 5
skipped`). The 5 skipped tests are the optional real-Tesseract integration
tests in `tests/test_pdf_ocr_tesseract.py`, which skip when the executable is
not discoverable; the deterministic suite requires no Tesseract.

## 5. Compatibility

* Preserved: `build_epub`, `Book`/`Chapter`/`Heading`/`Paragraph`/`Image`/
  `PageBreak`/`BookMetadata`, `extract_book`, `analyze_pdf`, the OCR API,
  `process_page(s)`, `reconstruct_processed_pages`, `processed_pages_to_book`,
  `convert_pdf_to_book`, the error hierarchy, and all exports of
  `kindle_converter`, `kindle_converter.pdf`, and `kindle_converter.epub`.
* Intentional changes:
  * `convert_pdf_to_epub` gained keyword-only `engine` / `renderer` / `dpi`
    parameters with defaults (existing positional calls are unaffected) and no
    longer raises `ScannedPDFError` / `MixedPDFError`.
  * `convert_pdf_to_book` now attaches M2.13 images to every classification.
  * `STYLESHEET_CSS` was evolved; class names used by the markup (`image`,
  `page-break`) are unchanged.

## 6. Scope check

M4.1 implements **only** the Kindle-ready EPUB foundation. It does not
implement: the M4.2 EPUB validator, AZW3/Calibre conversion, cover extraction
or generation, advanced Kindle typography/device hacks, GUI/web work, new OCR
or reconstruction algorithms, or unrelated refactoring. `Book.cover` remains
unused by the builder (M4.4 scope).

## 7. Known limitations

* EbookLib stamps `dcterms:modified` (and ZIP entry timestamps) into the
  container, so two builds of the same `Book` are logically — not byte —
  identical.
* `extract_pdf_images` (M2.13) has no size/format filtering: a scanned page's
  full-page image is carried into the `Book` and therefore packaged into the
  EPUB alongside its OCR text. Images whose media type the builder cannot
  resolve still raise `InvalidImageError` (existing M1.4 behavior).
* OCR-based conversion still needs Tesseract at runtime; without it, a
  SCANNED/MIXED conversion raises `OCREngineUnavailableError` (no silent
  empty book).
* `convert_pdf_to_book` still produces a single chapter per document; chapter
  splitting inside reconstruction remains a later refinement.
