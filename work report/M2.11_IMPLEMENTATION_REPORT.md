### 2. README requirement

The README's Milestone 2 requirement list includes **"Table of contents
generation"**. M2.11 establishes that operation: a dedicated, independently
testable public function that consumes the M2.9 chapter-detection result and
produces a small, immutable, deterministic `TableOfContents`. The README's
intended architecture already routes `chapter detection → page-number removal →
TOC generation` at the end of the reconstruction pipeline; M2.11 implements the
final TOC-generation stage of that chain.

### 3. Architecture

M2.11 consumes M2.9's own output rather than rediscovering anything. The
pipeline is:

```
PDF → layout (M2.1) → reading order (M2.2/M2.6) → paragraphs (M2.3)
    → headings (M2.4) → header/footer analysis (M2.5) → reconstruction (M2.7)
    → chapter detection (M2.9) → page-number removal (M2.10)
    → TOC generation (M2.11)
```

`generate_toc(source)` takes a
`kindle_converter.pdf.chapters.ChapterDetectionResult` (the return value of
`detect_chapters`) and maps each `DetectedChapter` in that result into one
top-level TOC entry. It never calls `detect_chapters` internally, never scans
raw PDF blocks, never independently infers chapter boundaries, never re-sorts
content, and never re-classifies headings. M2.9 is the sole source of truth for
chapter boundaries.

### 4. Data model

Two tiny frozen+slots dataclasses, consistent with the existing domain models:

- **`TOCEntry`** — one table-of-contents entry with:
  - `title` — the detected chapter text (preserved verbatim),
  - `order` — the 1-based chapter order established by M2.9,
  - `page_number` — the source page number where the chapter starts,
  - `level` — `TOC_CHAPTER_LEVEL` (always `1` in V1; see Known limitations),
  - `chapter` — the M2.9 `DetectedChapter` by reference (full provenance, never
    mutated),
  - `identifier` — reserved for future anchor integration, always `None` in V1
    (the document/EPUB layers do not yet provide stable book-level anchors, so no
    identifier is invented).
- **`TableOfContents`** — an ordered, immutable sequence of `TOCEntry` objects
  with an `entry_count` property.

The models reference only project-owned frozen dataclasses and know nothing
about EbookLib or EPUB internals.

### 5. Public API

```
generate_toc(chapters: ChapterDetectionResult) -> TableOfContents
```

- Consumes M2.9 output directly (`detect_chapters`'s return value); does not
  re-run detection.
- Returns an immutable, ordered, deterministic `TableOfContents`.
- Raises `TypeError` (consistent with `detect_chapters` / `remove_page_numbers`)
  when the argument is not a `ChapterDetectionResult`.

The same public symbols are exported at package level through
`src/kindle_converter/pdf/__init__.py` (`generate_toc`, `TableOfContents`,
`TOCEntry`, `TOC_CHAPTER_LEVEL`).
### 6. Ordering and provenance

- **Ordering**: the TOC iterates `ChapterDetectionResult.chapters` in the exact
  order M2.9 already produced. No alphabetical sorting, no title sorting, and no
  page-number-derived ordering are applied; tests lock this in (including
  non-alphabetical and non-monotonic page-number fixtures).
- **Page provenance**: each entry copies `order` and `page_number` from its
  detected chapter and also retains the whole `chapter` object, so a consumer can
  read the source page number or any upstream provenance without new detection.
- **Titles**: `title` is the detected chapter `text` verbatim — numbering, case,
  and punctuation are preserved exactly; nothing is rewritten or normalized.

### 7. EPUB integration

The M2.11 boundary is focused on TOC *generation* only. The existing EPUB layer
currently derives its EPUB navigation directly from the `Book.chapters` list
(`epub/builder.py` sets `epub_book.toc = chapters` and the spine from the domain
chapters), and the existing `reconstructed_document_to_book` adapter emits a
single logical chapter. Wiring the new domain `TableOfContents` into the EPUB
chapter/nav/ncx/navigation layer belongs more naturally to a later task
(M2.12/M2.13), so **no large EPUB rewrite was attempted here. The EPUB builder,
the document domain model, and the EPUB tests are untouched.** M2.11 instead
delivers a clean, EbookLib-independent TOC representation that future EPUB
integration can consume directly. An integration test proves the reconstructed
document → `detect_chapters` → `generate_toc` and the existing
`reconstructed_document_to_book` → `build_epub` path all coexist and remain green.

### 8. Tests

`tests/test_toc_generation.py` (50 tests) covers:

- Basic chapter TOC; exact title preservation; ordering follows M2.9 (never
  alphabetical or page-sorted); page provenance; duplicate titles stay separate;
  empty/no-chapter results produce a valid empty TOC; front/back-matter headings
  are excluded unless M2.9 declares them chapters; V1 is chapter-based (all
  top-level, ordinary section headings not promoted); numbering (arabic/roman/
  word) as supplied; punctuation/capitalization preserved; determinism across
  repeated and structurally-equal runs; immutability (frozen entries + source
  chapters unchanged by identity and content); invalid-input `TypeError`; public
  exports from the `pdf` package; and real M2.9 integration
  (document → `detect_chapters` → `generate_toc`) plus an end-to-end path to the
  unchanged EPUB builder.

### 10. Compatibility

No M1 or M2 behavior changed outside this task. The only production-file change

additive, explicitly invoked layer.

### 11. Known limitations

V1 intentionally does not support:

- A multi-level/section/subsection TOC hierarchy. Every chapter is a single
  top-level (level-1) entry because M2.9 exposes chapter boundaries, not a
  heading hierarchy.
- Recomputing printed page numbers. Only the M2.9-provided source page number is
  preserved.
- Per-entry EPUB anchors/identifiers. `identifier` is reserved and always `None`
  because the document and EPUB layers do not yet supply stable, book-level
  chapter anchors; no fragile PDF-coordinate identifier was invented.
- Routing the TOC into the EPUB nav/NCX. That belongs to a later milestone
  (see §7); M2.11 only produces the domain representation.
- Independent chapter or heading discovery of any kind; M2.9 remains the sole
  chapter source of truth.
