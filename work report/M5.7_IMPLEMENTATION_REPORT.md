# M5.7 Implementation Report — Errors + Temporary Files

**Project:** PDF to Kindle Converter
**Milestone:** M5.7 — Errors + Temporary Files
**Date:** 2026-09-18
**Status:** Complete

---

## Summary

M5.7 introduces an application-owned temporary workspace for every conversion. Each call to `ConversionApplication.convert()` creates an isolated temporary directory that exists only for the lifetime of that conversion and is deterministically cleaned up on exit — successfully or on any failure path. A `WorkspaceError` exception class handles workspace creation failures, and cleanup failures are logged but never replace the original conversion failure.

---

## Requirements Addressed

| Requirement | Implementation |
|---|---|
| Application-owned temporary workspace | `ConversionWorkspace` context manager using `tempfile.TemporaryDirectory` |
| Deterministic cleanup on all paths | `__exit__` calls `cleanup()`; `convert()` also calls `cleanup()` in `finally` |
| Workspace path exposed to application code | `workspace.path` property available after context entry |
| Workspace not user's output directory | Final artifacts (EPUB/AZW3) written to user-selected output dir; workspace cleanup never touches it |
| `WorkspaceError` for creation failures | `WorkspaceError(ApplicationError)` raised when `TemporaryDirectory()` fails |
| Cleanup failures don't replace original failure | `cleanup()` catches `Exception`, logs warning, never raises |
| Workspace owned by application layer | Created and managed in `ConversionApplication.convert()`, not in GUI or worker |
| No artificial temporary files | No production code creates files solely to demonstrate the abstraction |
| No redesign of UI/worker/pipeline | Zero modifications to UI, worker, or pipeline files |

## Error Handling Architecture

### Error Hierarchy
```
PipelineError
  └── ApplicationError
        ├── InvalidRequestError
        ├── ConversionFailedError
        ├── OutputError
        ├── ValidationFailedError
        ├── AZW3OutputError
        └── WorkspaceError          ← NEW (M5.7)
```

### Error Flow
1. **Workspace creation failure** → `WorkspaceError` raised from `__enter__` → propagates through `convert()` → caught by worker as `ApplicationError` → surfaced in UI as failure message
2. **Cleanup failure** → logged as warning via `logger.warning()` → original exception propagates unchanged
3. **WorkspaceError in worker** → `ConversionWorker` catches `ApplicationError` → emits `failed` signal with error → UI shows error message, restores controls

### Why No UI/Worker Changes
`WorkspaceError` is a subclass of `ApplicationError`, which is already handled by:
- `ConversionWorker.run()`: Catches `ApplicationError` separately from unexpected exceptions, emits `failed` signal
- `MainWindow._on_conversion_failed()`: Displays `ApplicationError` message verbatim, restores UI controls
- `MainWindow._on_conversion_succeeded()`: Not affected (workspace cleanup happens before success)

## Design Decisions

### 1. `cleanup()` catches `Exception`, not just `OSError`
`TemporaryDirectory.cleanup()` typically raises `OSError`, but catching `Exception` ensures no cleanup failure (e.g., permission issues, filesystem errors) can ever replace the original conversion failure. Cleanup failures are operational, not programming errors, and the spec requires they never replace the original.

### 2. Redundant cleanup in `convert()`
`convert()` calls `workspace.cleanup()` in a `finally` block, but `with workspace:` already calls `cleanup()` via `__exit__`. This redundancy is intentional: the `finally` guarantees cleanup runs even if the `with` statement itself fails unexpectedly (e.g., during `__enter__` failure propagation). `cleanup()` is idempotent, so double-cleanup is a no-op.

### 3. `ConversionWorkspace` exported from `application/__init__.py`
The workspace is a small application-layer abstraction that callers may need to reference (e.g., for testing or for advanced use cases). Exporting it from the package root improves discoverability.

### 4. No workspace path passed to `_convert()`
The spec says the workspace path should be "exposed to application code that needs intermediate artifacts." Currently, no application code needs intermediate artifacts, so the path is available via `workspace.path` inside the `with` block but not passed to `_convert()`. This avoids creating artificial file paths.

### 5. No UI tests specifically for `WorkspaceError`
`WorkspaceError` is an `ApplicationError` subclass, so existing UI tests that use `ConversionFailedError` and `ApplicationError` already cover the surfacing mechanism (error message displayed, controls restored, `CONVERSION_FAILED` state). Adding explicit `WorkspaceError` UI tests would test the same mechanism with a different exception type — the behavior is identical due to inheritance.
