# M6.3 — Conversion Quality Measurement: Implementation Report

## 1. Summary

Milestone 6.3 adds a deterministic, corpus-driven **conversion-quality measurement layer** that answers a deliberately different question from the M6.2 regression suite: not "did the converter's structural output change?" (regression pins exact, deterministic behavior in `tests/fixtures/regression_baseline.json`), but **"does the conversion output have good quality?"** The new suite runs every M6.1 fixture through the real public pipeline — `convert_pdf_to_book` / `convert_pdf_to_epub` plus the `analyze_pdf` → `extract_page_layout` → `reconstruct_layout` → `detect_chapters` → `generate_toc` path — with the deterministic injected OCR engine, measures defined quality facts, and evaluates them against **authored, human-written quality expectations** committed in `tests/fixtures/quality_baseline.json`. It never invokes Tesseract or Calibre, needs no network or GUI, and produces no single numerical "quality score": every fixture/metric/expected/observed/status/details triplet remains visible in both the human-readable and machine-readable reports.

The framework is organized as a small package under `tests/quality` (mirroring the M6.2 `tests/regression` design): `baseline` (loading/validation), `expectations` (schema + evaluators for `exact`, `minimum`, `maximum`, `contains`, `excludes`, `boolean`, `ordered_sequence`), `harness` (the `QualityObservation` measurement), `evaluation` (per-fixture + corpus verdicts), `report` (human + machine), and `regenerate_baseline` (an explicit maintenance script). Regeneration is explicit and guarded: `exact` pins follow a fresh measurement, every other authored expectation is preserved verbatim, and `--write` **refuses to persist over a failing authored expectation** — a failing expectation is reported as a finding, never silently weakened or auto-tolerated.

The suite is fully green against the current converter: **all 11 fixtures pass their authored expectations** (classification, structure, reading order, OCR routing, images, EPUB). It also surfaces two honest converter gaps as recorded observations/review notes rather than hidden values: EPUB chapter splitting is absent (the PDF layer detects up to 8 chapters and TOC entries for `chapters_long`, yet every EPUB ships a single chapter with one nav entry), and the deliberately conservative M2.4 heading detector does not promote document titles (e.g. "Minimum Viable Document", "On the Behavior of Light") to headings while explicit `Chapter N:` headings are surfaced. Both are documented as follow-up opportunities, not masked.

## 2. Architecture

```
tests/quality/                      # M6.3 measurement framework (new)
├── __init__.py                     # package docstring only (import-light, like tests/regression)
├── baseline.py                     # quality baseline load + structural/schema validation
├── expectations.py                 # expectation model, vocabulary, aliases, evaluators
├── harness.py                      # QualityObservation + observe_quality() measurement
├── evaluation.py                   # evaluate_fixture() / evaluate_corpus()
├── report.py                       # build_machine_report() / format_human_report()
├── regenerate_baseline.py          # measure → preview diff → --write (guarded)
├── conftest.py                     # session-scoped observations / baseline / results
├── test_quality_expectations.py    # expectation schema + evaluator unit tests
├── test_quality_harness.py         # measurement surface over the real corpus
├── test_quality_baseline.py        # baseline load/validate/coverage/schema discipline
├── test_quality_evaluation.py      # per-fixture + corpus verdicts, failure visibility
├── test_quality_report.py          # report contract, determinism, no timestamps/paths
└── test_quality_regenerate.py      # regeneration preservation + --write guard
```

**Measurement flow** (one fixture): `analyze_pdf` (classification) → `convert_pdf_to_book` with `CountingOCR` (paragraphs/headings/images/page-breaks, empty/near-empty artifacts, OCR call count, body text) → `extract_page_layout`/`reconstruct_layout`/`detect_chapters`/`generate_toc` (PDF-layer chapters + TOC entry count) → `convert_pdf_to_epub` (EPUB validity, chapter files, heading tags, nav entries, empty chapters, page breaks, image resources) → `epub_pages` + a `\b[LR][1-4]\b` token pattern (reading-order sequence). The EPUB is written to a temp (or caller-supplied) directory during observation and only **derived facts** survive in the frozen `QualityObservation`; no timestamps, no absolute paths, no randomness.

**Classification is the single data source of truth**: the baseline deliberately stores no classification expectation; `evaluate_fixture` derives the expected classification from `manifest.json` at evaluation time (like M6.2 does for the corpus metadata). The corpus manifest remains the single source of truth and is not duplicated.

## 4. Quality dimensions

Each fixture is measured across the dimensions that apply to it:

| Dimension | What it measures | Metric examples |
|---|---|---|
| `classification` | manifest-driven PDF-type check (never stored in baseline) | `classification == manifest.expected` |
| `structure` | paragraphs, detected headings, PDF-layer chapters, TOC entries, page breaks (= pages−1), empty/near-empty paragraph artifacts, body-text content anchors, OCR-marker exclusion | `paragraphs ≥ 12`, `headings ≥ 3`, `contains`, `excludes` |
| `reading_order` | two-column left/right `L1..R4` token sequence | `column_tokens` as `ordered_sequence` (24 tokens over 3 pages) |
| `ocr` | pages routed to OCR via `CountingOCR`, OCR marker presence, no real-OCR-engine leak | `ocr_calls`, `ocr_text_present`, `contains`/`excludes` |
| `images` | image blocks in the Book and deduplicated image resources in the EPUB | `image_blocks`, `epub_image_resources` |
| `epub` | `validate_epub` validity, chapter files, heading tags, nav entries, empty chapters, EPUB body anchors | `valid` (boolean), `chapter_files`, `heading_tags`, `nav_entries`, `empty_chapters`, `contains` |

Expectation types used: `exact`, `minimum`, `maximum`, `contains`, `excludes`, `boolean`, `ordered_sequence`. Only these seven were implemented (per the milestone's "genuinely needed" rule); they cover every authored expectation in the baseline.

## 5. Baseline

`tests/fixtures/quality_baseline.json` (schema version 1) holds per-fixture:
- a human-authored `notes` list (manual-review reminders, e.g. "verify figure placement and caption adjacency", "confirm the native/OCR text split on the fully mixed page");
- dimension → metric → `{type, expected}` entries.

Authored expectations encode *quality claims*, not regression snapshots: floors ("at least 12 body paragraphs", "all 8 chapters detected"), ceilings ("no empty/near-empty paragraph artifacts"), content anchors ("`by Ada Grant` survives", "`Chapter 1: The Harbor` reaches the EPUB"), exclusion rules ("no `OCR-TEXT-FOR-CALL` in body text", "no `Tesseract` string"), booleans ("PDF type matches manifest", "EPUB validates"), and the ordered reading-order sequence for `twocolumn_article`.

Regeneration (`python -m tests.quality.regenerate_baseline`) mirrors M6.2's review-first pattern: it diffs the fresh measurement against the committed baseline, updates only `exact` pins from the measurement, preserves all authored expectations verbatim, reports any **authored** expectation that now fails as a finding, and — uniquely — refuses to `--write` over such a failure (`exit 2`). Re-running against the committed baseline is currently idempotent (no expectation value changes), which the test suite asserts.

## 6. Reporting

`tests/quality/report.py` renders the same evaluation two ways, both pure functions of the results and both free of timestamps and machine paths:
- **Machine-readable** (`build_machine_report`): JSON with `schema_version`, `report: "m63-quality"`, `corpus_size`, `fixtures_passed/failed`, and a per-fixture `status` + per-dimension `status` + per-metric `{metric, type, status, expected, observed, details}` — individual measurements are never hidden behind a single number.
- **Human-readable** (`format_human_report`): a per-dimension PASS summary plus a per-fixture breakdown showing every expectation's `expected`, `observed`, `status`, and stabilising details (e.g. "missing required content: …", "sequence mismatch"), followed by the review `notes`. Failures are printed as findings; the footer reminds maintainers to fix the converter, not the expectation, unless reviewed via the regeneration tool.

A session-wide probe report (all 11 fixtures) showed 11/11 fixtures PASS across 171 evaluated check results (11 classification + 160 authored metrics: structure 70, ocr 28, epub 55, images 6, reading_order 1).

## 8. Determinism

The framework is deterministic by construction and this is pinned by tests:
- OCR is the injected `tests.regression.harness.CountingOCR` (a deterministic call counter replying `OCR-TEXT-FOR-CALL-<n>`); Tesseract is never invoked, so the default run needs none of the optional OCR tools;
- `observe_quality` reads the PDF from the committed corpus, uses only public APIs, and returns a frozen, path-free `QualityObservation`;
- observations carry no timestamps, no absolute paths, no randomness — `test_observation_is_deterministic()` re-measures `edge_short_report` and asserts identical results;
- both reports are pure functions and byte-identical across repeated invocations (`test_machine_report_is_deterministic`, `test_human_report_is_deterministic`);
- no network, no Calibre, no GUI is required at any point.

## 11. Defects discovered

The measurement surfaced two honest converter gaps — recorded as per-fixture `notes` and visible in the reports, **not** hidden behind expectations or auto-tolerated:

1. **EPUB chapter splitting is absent.** The PDF layer detects and indexes chapters (`novel_basic`: 3, `twocolumn_article`: 3, `chapters_long`: 8 detected chapters and 8 TOC entries via `detect_chapters`/`generate_toc`), but the EPUB generator always renders a single chapter file with `<nav>` entries = 1 (`chapter_files = 1`, `nav_entries = 1` for every fixture). The quality baseline asserts `nav_entries >= 1` and flags the divergence in the `chapters_long` review note as follow-up work outside this milestone.
2. **Document titles are not detected as headings.** The M2.4 heading detector is deliberately conservative: the corpus's title/front-matter lines are classified as body text rather than headings (`textbook_dense`/`chapters_long`/`novel_basic` title lines do not appear in `heading_texts`; explicit `Chapter N:`-style headings always are). The quality expectations assert the observable behavior (e.g. `novel_basic` `headings >= 3`, `textbook_dense` `headings >= 13`) without weakening detection thresholds.

An additional, neutral observation recorded in the reports: the EPUB image resource count is deduplicated relative to Book image blocks when figures repeat (`text_with_images`: 4 blocks → 3 resources), which is correct asset handling but worth the reader-visual check noted.
